# Lucidchart SVG benchmark v1 independent review — 2026-10-07

## Review scope and protocol

This is an evaluator review of the new benchmark, not a skill mutation or a
replacement for its artifact oracles. The reviewed skill source stays frozen.
The previous eight-run compatibility cohort is historical evidence and is not
pooled with this benchmark. The current source runtime digest is
`0e4d5c69add73792b268cb0890edbb48d39c573e1fdb9a908ba017ad50679f93`.

The planned benchmark has eight cases and eighteen fresh isolated runs:
contract (1), geometry (3), relations (3), asset (3), boundary (1), ambiguity (1),
semantic (3), and generated layouts (3). The three-run cases require at least
two joint passes out of three. A single run is sufficient for an exact command
contract or deterministic guard case. Keep all attempts, including failures;
do not repair or replace candidate artifacts. The recorded evaluation-only
`openai-codex/gpt-5.6-luna` exception follows the earlier Spark account/provider
rejection before tools. Model, prompt, source-payload, output, and oracle
identities must remain attached to each result.

A run passes only when all applicable layers pass:

1. Strict harness checks: exact nonempty output files, observed model, valid
   event JSON, no tool errors, unchanged read-only runtime payload, and isolated
   reads.
2. Evaluator-owned checks against the task inputs: source identity, geometry,
   topology, literal content, documented local package fields, and exact output
   contracts.
3. Command and read review, including indirect shell reads and prohibited
   network, repository discovery, or external-state changes.
4. Direct artifact and narrative review: task correctness, semantic fidelity,
   truthful adaptation/omission notes, and accurate local-versus-live status.

Candidate-produced reports and matching ZIP/document JSON are useful
consistency evidence. They do not establish that the result satisfies the
input. The independent oracles must not import or rerun skill implementation,
derive their expectations from candidate reports, or require incidental
formatting that the task did not request. Numeric assertions should use tight
tolerances and independently derived transforms, boxes, and attached ports.

## Coverage and scoring critique

The eight-case split is a useful expansion over the prior rich-native,
resource-boundary, two-node SVG, and generated-family fixtures. Each new case
must supply fresh data and test a distinct decision or preservation property;
three copies of one prompt demonstrate repeatability rather than disjoint
holdout coverage. A naturalistic case should leave the implementation route
open. Exact catalog fields or helper commands belong in the contract case only
unless they are input data supplied by the user.

Preserve supplied SVG bytes explicitly. Compare original bytes against the
prompt's agreed UTF-8/newline contract, without evaluator normalization after
the run. Prepared artwork copies should remain identical unless the user asks
for a separate, declared derivative. Reject silent removal of painted content,
fabricated topology, formal roles inferred from shape resemblance, and any
complete-looking graph that drops unresolved source meaning.

Expected refusals need a useful diagnostic and an accurate incomplete status.
They do not become successes merely because a diagnostic exists. Known
preflight blockers should stop unchanged-source extraction; uncertain bounded
extraction may be diagnosed with a captured expected return code. Review this
distinction against the strict tool-error gate instead of relaxing that gate.

Manual review must catch factual narrative errors independently of structured
reports. Examples include assigning a dashed border to the wrong node,
calling an unstroked path visibly directed, treating outlined paths as known
literal labels, or claiming a live edit/import/export from local compilation.
No visual-equivalence percentage should be derived from counts, a local SVG
preview, or screenshots at incompatible scales.

## Evidence limits

This benchmark can establish tested local XML preparation, reconstruction,
package generation, and agent workflow. It cannot establish authenticated SVG
download, formal custom-SVG insertion, Standard Import service parsing and
rendering, native editing, font availability, connector-following behavior, or
generated-layout reflow. Those limits persist even if every local case passes.
The backlog should remain `validating` until the live routes have direct
evidence.
