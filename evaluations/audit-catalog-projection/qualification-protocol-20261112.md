## Cases, grouping and independence

The public development dataset has two composite tasks with five concrete
input-pair scenarios each. Ten scenarios exercise moved pointers, homonym
separation, typed absence, record boundaries, alias multiplicity, ordered keys,
escaped pointers, per-side ID paths, category separation, and declared scope.
The two tasks share authoring, instruction and oracle ancestry, so conservatively
count them as ONE public benchmark family. Ten scenario checks and repeated
attempts are not ten independent source families or ontology-authoring cases.

The independent curator supplies two new private task roots with materially
different goals, raw sources, response forms and manually checked oracles.
They form the mandatory holdout dataset. Keep the entire old three-target
validation cohort unconsumed. The curator/peer reviews source/template/oracle
ancestry and near-clone risk before registration and binds the exact dataset
and task digests in the six-check design receipt. A changed filename or seed
does not create an independent family. Shared public helper/API semantics are
the treatment specification, not a hidden answer.

Every public case has manually authored expected source/projected field views
and differences. A separate verifier checks report claims against those views;
the helper is not its own unchecked oracle. Two valid presentations and at
least eight plausible invalid-output controls per public task, all private
controls, source-integrity checks and actual packaged native Oracle must pass
before any model job. Keep all QA outside immutable task roots.

## Ordered budget and hard gates

The immutable task-model cap is20physical attempts:

1. Public broader-control job: two tasks times two attempts =4.
2. Public fixed new-skill job: the same two tasks times two attempts =4.
3. Physically fresh public replay of the same new skill: another4.
4. Only after the whole public gate, one holdout release: two tasks times two
   attempts times control/new skill =8, in two complete native jobs.

Run all12public attempts and report them even if an early result fails. The
new skill must qualify8/8public attempts with zero errors, all required reward
keys complete, unchanged bundles/inputs, and identical helper reports for each
same-task repeated pair. This deliberately strict pilot gate is not a general
population accuracy estimate. If it fails, stop the holdout and retain the
prototype without promoting a runtime skill. No new candidate is selected.

Public completion is the fixed candidate selection ancestor for the holdout.
Record the frozen candidate before release. The holdout candidate must qualify
all4attempts with zero errors, complete required rewards and source fidelity.
Apply every private task and criterion jointly; no partial feedback is returned
until all8paired attempts finish. Native result reports own qualification,
fairness and metrics. Missing or non-evaluable evidence fails the gate.

Source-backed interpretation in private tasks is checked independently of report
byte equality. Canonicalize only declared presentation alternatives, preserving
IDs, typed values, definitions, roles, qualifiers, before/after direction and list
scope. Missing outputs never establish agreement. Freeze the independent
inspection rules before any private output. Never substitute gold hashes when
a verifier passes. Keep raw report equality separate from qualified correctness.

## Reporting and release limits

Report requested/completed/passed/verifier-failed/error counts, native required
rewards, repeatability, exact skill digests, fairness basis and resource metrics
with their native coverage. Use the owning native reporter; do not invent a
pooled score or rescore trials. Control/candidate equality supports a scoped
capability addition and nonregression, not an extraction-accuracy gain. Report
all failed required strata and the final acceptance decision.

Only if the whole pilot passes, publish this new skill with a scoped qualification
note. Retain the other three skill sources. Do not claim free-text ontology
correctness, OWL consistency, automatic semantic equivalence, ten independent
ontology cases, real-world crawler coverage, or reliable automatic skill routing.
All structural reports keep semantic_status=not_checked. Report hashes are local
canonical field views, not an RFC8785/JCS interoperability guarantee.

No significance claim or global-best ranking is justified by this small authored
pilot. Publish aggregate source-linked metrics, source hashes, deterministic
controls and known limitations. Keep private prompts, IDs, answers, filenames,
traces and machine-local paths out of Git and optimization feedback. Private
outcomes cannot support same-study tuning, even if the fixed candidate fails.

## Repeatability units clarified before sealing

Public tasks supply fixed immutable contracts. Require identical raw helper
reports in each same-task pair: four candidate pairs across initial and fresh
public jobs. The private tasks allow the agent to author a contract; incidental
JSON object/contract-field order can change contract_sha256 and report bytes.
For the private candidate, require two qualified equal semantic-core pairs,
preserving every meaningful field, stable ID, typed value, selected scope,
direction, role, qualifier, source binding and list hierarchy. Normalize only
the declared incidental representation differences. Keep raw helper-report
byte equality and contract-byte hashes as separately reported representation
metrics; they do not fail the private repeatability gate when only the declared
incidental serialization/contract-field ordering differs. All four candidate
private attempts must still pass the complete source-bound native verifier
with zero errors. Freeze and independently review the inspector before models;
never use a verifier outcome as a substitute for hashing the actual artifact.
