# Slidev layout template contract

Prepare an editable deck at `deck/` with the loaded skill's bundled `assets/templates/slidev-layouts/` runtime pack. Copy the whole contents of that runtime pack into the same relative paths inside the deck. Write `deck/slides.md`, `deck/package.json`, `deck/components/CollectionStory.vue`, `deck/data/cards.json`, and `deliverables/layout-review.md`. Declare Slidev, Vue and `@slidev/theme-default` in the package. Do not install dependencies or build in this narrow contract; the evaluator will supply dependencies and render separately.

Create exactly four slides. Use CollectionStory as a small adapter around the copied reusable layout pack. Pass the native Slidev click state to the wrapper. Use one of these modes on each slide, in order: `columns`, `grid`, `masonry-rows`, `masonry-columns`. The masonry-rows slide must use exactly three literal horizontal rows, rather than a three-column layout. For the other three modes, click states 0, 1 and 2 use two, three and four columns. Every slide shows three, seven and eleven cards in those click states. Do not shrink fonts or crop text to fit. If the chosen container cannot hold all cards at a readable size, explicitly paginate with controlled `page`/`pageSize`, show the current page/count, and provide accessible page controls named Previous page and Next page. Every card must remain reachable, with no clipped published state.

Store all eleven cards as JSON data with stable IDs `card-01` through `card-11`. Their titles, in order, are Intake, Scope, Research, Draft, Diagram, Review, Revise, Check, Approve, Publish and Archive. Write a brief explanatory body for each, varying its length from one to three short sentences. Provide variable card widths for horizontal masonry and naturally measured variable heights for vertical masonry. Keep a complete categoryOrder manifest for all eleven card identities, including hidden cards, and pass the same manifest on every slide. Use colorset1 and the bundled black/white text-contrast logic. Keep fills stable through clicks, ordering changes and pagination. Use labels or numbering so readers can follow the source order.

Use normal data and props for the dynamic count and dimensions; do not manually position a separate rectangle for every card count. Read only the specific local layout reference and template files required for this task. Follow the skill's supported layout/capacity check path instead of inventing a Markdown slide-count formula.

In the review file, record the selected palette, copied runtime files, the data/identity contract, literal-row versus column masonry semantics, pagination/capacity policy, and local build/check commands. Do not claim browser verification that has not occurred.

Treat `skills/slidev-animejs/` as read-only. Generated task files belong outside it. Do not read acceptance examples, other skills, repository documents or files outside this isolated workspace. Do not publish anything.
