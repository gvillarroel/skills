# Slidev HyperFrames integration contract

Create an editable three-slide deck at `deck/` using the loaded skill's local HyperFrames integration. Copy the whole contents of `assets/templates/slidev-hyperframes/` into the same relative paths in the deck and keep those reusable resources unchanged. Write the exact paths `deck/slides.md`, `deck/package.json`, `deck/components/HyperframeStory.vue`, `deck/data/hyperframes-story.json`, and `deliverables/hyperframes-review.md`. The copied pack must also create `deck/components/HyperframeSlide.vue`, `deck/lib/hyperframes.js`, `deck/public/hyperframes/starter.html`, and `deck/public/hyperframes/scene.js`, along with every local runtime, palette and font asset it needs. Declare Slidev, Vue, the selected theme and the skill's pinned player dependency in package.json. Declare package scripts `build` and `build:html`. The production build serves over HTTP; `build:html` writes a self-contained direct-open file at `deck/dist/slidev.html`, including a working local or inline Open Sans face. Do not install dependencies or build; the evaluator will install exactly the submitted dependencies in a disposable deck copy and run those scripts.

Use HyperframeStory as a small deck adapter around the bundled player component. Use the local starter composition. Slide 1 is a large live view titled "How the level changes". Slide 2 is titled "A reusable live cell" and places the same live composition in one cell of a configurable two-column layout, with a concise explanation in the other cell. Keep the player within the measured inner dimensions of its cell. Slide 3 is titled "Exported handoff" and displays the deterministic composition state at 9 seconds using the supported static/export path.

Store `cueTimes: [0, 4, 9]`, `exportTime: 9`, and `colorset: "colorset1"` in the editable story JSON. Both live slides start at 0 seconds and use two actual Slidev clicks to apply 4 and 9 seconds. Pass the native Slidev click state and lifecycle to the integration; backward clicks must restore the corresponding actual composition state. Provide a preview control with the accessible names Play animation and Pause animation in its relevant states. Preview must make the actual scene advance. Leaving a slide stops its hidden playback, and returning restores the selected cue. Avoid duplicate player instances or listeners after repeated visits.

Use colorset1 and Open Sans in both host content and the iframe composition. Let the bundled starter provide its palette and black/white contrast defaults. Use only local composition, runtime and font assets; no CDN or network recovery. Preserve full readable labels and readouts in the hero and cell, including when the available layout width narrows from its initial width to 680 CSS pixels. Do not crop text or shrink fonts to fit. Keep publication states inside the slide viewport. A direct-open HTML export must use the supported accessible deterministic fallback when live iframe loading is unavailable and must not remain a loading or error placeholder.

In the review, record the copied resources and dependency pin, cue/click contract, local asset policy, actual cell sizing policy, preview cleanup, static versus direct-open export behavior, and build/check commands. Do not claim browser checks that have not occurred. Follow the skill's supported static checker rather than inventing a Markdown separator count.

Treat `skills/slidev-echarts/` as read-only. Write generated files outside it. Read only needed local runtime references, templates and scripts. Do not read acceptance examples, sibling skills, repository documents or files outside this isolated workspace. Do not publish anything.
