# Skill authoring and generated-bundle review — 2026-10-02

## Scope and evidence boundary

This review applies the [Claude Platform skill authoring guide](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
to the canonical Codex skills and the bundles actually distributed to agents.
It began with 33 skills. `hyperframes-explainer` was added by another active
chat during the review and is included in the final inventory with its own
separate release evidence. The review does not promote unrelated unfinished releases.

The assessment includes metadata, concision and navigation; manual entrypoint
review of workflow, defaults, freedom, feedback and dependencies; real copied
runtime/full payloads; local installation checks; unforced metadata selection;
isolated D3 use; and fresh reviewer generation plus use of the generated skill.
Previous per-skill behavioral evidence remains attached to each backlog row.
Those prior releases were not all rerun in this authoring pass. Claude model
families and future models were not tested; the source guide informs authoring
policy rather than a claim of cross-provider certification.

The final structural inventory passes all 34 sources and 68 actual copies,
with zero findings. The 425 runtime Markdown references have direct routes;
the longest entrypoint body is D3 at 324 lines. The [D3 closeout](20261002-d3-validation.md)
passes all eight frozen strict/independent/manual runs and restores D3 to `done`.
Current canonical release statuses are 22 `done` and 12 `validating`;
other workflows retain their own evidence and release limits.

All earlier unrelated work was preserved. Canonical edits are under `skills/`.
Generated runs, screenshots, previews, and installation backups remain ignored.
No published example or canonical pattern ID was changed by this audit.

## Findings and repairs

The initial [machine audit](20261002-before.json) identified 348 findings:
89 long references without contents, one invalid contents list, 256 references
without a direct entrypoint route, and two files with Windows resource paths.
The later voice review also found imperative capability descriptions.

- Added or repaired linked contents in 90 references, preserving their guidance.
- Linked each runtime Markdown reference directly from its owning `SKILL.md`.
  Directory shortcuts and intermediate indexes no longer substitute for a direct
  route. Large recipe collections use short links and selective read instructions.
- Normalized capability descriptions to third person, preserving triggers and
  domain terminology. Manually corrected noun/verb ambiguities left by the
  transformation helper. Quoted the new HyperFrames description to repair its
  colon-bearing YAML scalar.
- Replaced Windows resource-path examples with forward slashes.
- Extended the standalone reviewer validator to enforce the same authoring
  contracts on generated reviewers. Required direct references, valid contents,
  metadata bounds, UTF-8, and entrypoint limits now travel with the generator.
- Promoted observed reviewer-use failures into its operational guidance:
  commands bind to a verified checkout or disposable copy, and expected child
  statuses are recorded without becoming failed outer tool operations. The
  concrete comparison adapter preserves unexpected failures.
- Preserved and archived 39 obsolete installed reference files before removing
  them from `.agents/skills/`. Their exact bytes and SHA-256 values remain under
  the ignored project installation archive. Canonical files were not deleted.

The standalone gate enforces the repository's stricter name limit of 63
characters, the description limit of 1,024 characters, and bodies below 500
lines. It rejects duplicate YAML keys, XML delimiters, invalid names, unrouted
references and broken contents anchors. Repository checks additionally enforce
resource resolution, script conventions, payload placement and independence.
The inventory records actual entrypoint sizes and reference counts.

## Manual authoring assessment

The inventory below records the implementation and feedback path reviewed for
each skill. This is a guidance assessment, not a substitute for executing every
script or certifying every generated artifact.

- Fragile operations use parameterized deterministic helpers and explicit
  input/output contracts; creative judgment remains open where the task needs it.
- Defaults are concrete, overrides retain the user's exact paths and source
  facts, and fallback/coverage language preserves unavailable checks.
- Selective references keep implementation detail out of the entrypoint.
  Large galleries and acceptance fixtures remain maintenance resources.
- Script invocation and dependency setup are distinguished from source reading.
  Validators and medium-specific review provide repair loops and honest limits.
- Pinned upstream versions and provenance dates remain explicit; the audit did
  not replace verified snapshots with moving “latest” dependencies.
- Terminology was reviewed within each workflow. Renderer/API names, source IDs,
  and exact contract literals were preserved.

## Distribution gates

The [authoring policy](../../docs/skill-authoring.md) documents these commands:

```sh
uv run --script scripts/validate-skills.py
uv run --script scripts/audit-skill-authoring.py --check-bundles --output evaluations/skill-authoring/20261002-bundles-validated.json
uv run --script scripts/sync-local-skills.py
uv run --script scripts/sync-local-skills.py --check
```

The audit creates actual runtime and full copies of every canonical skill,
checks their resources and authoring, and compares every copied file with the
expected source-profile hashes. It freezes the complete inventory and rejects
source changes or added/removed skill directories at audit completion, including
edits to skills checked earlier in the loop.
Runtime copies exclude acceptance examples, dependencies, caches and build
output; full copies retain acceptance fixtures and exclude dependency/build
output. Neither profile may omit a required runtime resource.

Source and destination validation run before/after local installation and before
an isolated Pi launch. CI runs the standalone authoring, generated-reviewer,
copy/install and harness regressions, then audits both payload profiles before
Pages publication. An arbitrary generated skill can be checked without a
backlog row using `validate-skills.py --skill <path> --profile runtime`.
