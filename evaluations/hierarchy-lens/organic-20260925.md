## Retained failures and fixes

- **Agent:** Generalization trial 2 explicitly requested one logical pixel per record. The agent read the compact reference, which documents `--cell-pixels 1`, but ran `--cell-pixels 2`. Its HTML therefore has four pixels per record. Strict JSON assertions correctly reject it; successful rendering does not override the request. Trials 1 and 3 preserve the exact one-pixel requirement. The failed attempt is retained and not counted as a pass.
- **Implementation, repaired before forward trials:** The first odd-width centering expression placed a one-pixel root left of the central display pixel. Using `size//2-cellPixels//2` fixes it; deterministic tests cover widths 1, 3, and 4, and the one-pixel browser boundary passes. All reported Pi runs use the corrected frozen payload.
- **Validator setup:** A first local navigation probe opened the main catalog through a `file:` URL. Its directory link opened a file listing instead of resolving `index.html`, so the ready-state wait timed out. The corrected publication checker serves `dist/pages/` over localhost HTTP, matching Pages directory-index behavior. No renderer change was needed.
- **Published navigation, repaired:** The HTTP probe found that a legacy hash opened in an already-loaded organic page did not redirect: the initial redirect ran only at page load. The example builder now also handles `hashchange`. This changes only the published fixture, leaving the validated runtime payload unchanged. The browser check exercises this same-document transition as well as navigation between all three views.
