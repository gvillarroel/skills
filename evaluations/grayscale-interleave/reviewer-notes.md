## Scope and baseline preservation

The contract review compares the canonical JSON and all thirty copied palette
owners against baseline `daaee75353c63ed6dde204d57cfdbae6b9936586`. Its independent
expected replacement changes only Colorset1 `sequence`, `solidSequence` and
`categoryPriority`. Equality of all other fields protects token membership,
semantic roles, text choices and the complete Colorset2 definition. The native
allocator tests remain necessary: a matching copied JSON alone cannot prove that
a renderer consumes it. No substantive issue was found in that boundary.

conversion, report-consolidation or animation workflows. Passing these tasks must
be reported as narrow palette-allocation evidence, with owning native tests
reported separately.

## Native oracle and command evidence

The reviewed oracle resolves metadata-bearing groups to distinct painted shapes,
checks ancestor opacity, display and visibility, verifies complete category text,
inside-label bounds, fill order, canvas exclusion, overflow border contrast and
protected quantitative order. The repairs address the original double-counting
of group metadata and omitted label/quantitative opacity checks. The initial
oracle and its eighteen-row report remain under
`projects/grayscale-interleave/artifacts/reviews/oracle-v1/`; original Pi traces,
run manifests and strict results remain in their original run directories.

The exact-command sidecar independently replays the existing event checker with
prompt-first, observed-model, JSON/tool-error and exact-command requirements. It
adds evidence without changing original strict results. Fourteen completed
contract traces passed the sidecar at this snapshot. New contract invocations
also request `--require-exact-command-from-prompt`. Final collection must bind
this supplemental evidence to each exact retained run and its input hashes.

Two implementation details were found in the initial reviewed oracle snapshot
and then repaired by the root agent:

- Canvas discovery requires a full-covering white rectangle. The task says to
  paint a white canvas but does not require that geometry; an opaque white SVG
  CSS background is another valid painting method. Accept equivalent native
  backings or explicitly constrain the task before treating their absence as
  an artifact failure. The repaired oracle now accepts an opaque white SVG
  CSS background when no covering backing rectangle exists.
- A quantitative caption not wholly contained in its own swatch is assigned a
  white backing by assumption. Require its bounds to be disjoint from every
  painted mark, or determine the actual backing; partial overlap or overlap
  with another swatch must not inherit white contrast. A read-only bounds check
  of all fifty currently reviewed runs found no such external-caption
  intersections, so this is not an observed accepted false pass in that set.
  The repaired oracle now rejects external captions intersecting any actual
  category or quantitative key mark, including partial intersections.

## Cohort selection and retention requirements

Require a current-source strict contract plus at least two joint strict/native
passes from one complete three-repetition naturalistic cohort with the same
prompt and frozen payload. Keep all three outcomes, including any failure.
Choose a complete new cohort after prompt revision; do not assemble the best
individual runs across original and amended prompts. Retain each prior cohort,
its prompt, manifest, event stream, strict result, output and native review.

The runner uses fresh revision prefixes and the harness's existing-run guard.
Repeating an identical prefix would overwrite project-side dispatch summaries
before the harness refuses a reused run; do not reuse a prefix for recovery.
Final selection lineage is pending at this review snapshot. It should state why
a new whole cohort was selected, preserve the old whole cohort, bind prompt and
payload hashes, and distinguish narrow authored-key evidence from native
renderer or full-workflow claims. No final acceptance verdict is made here.

## Whole-cohort collector and recipe revision review

A subsequent read-only code audit reviewed `collect_acceptance.py` at SHA-256
`1e468cdc38e2cba5acd6a4de91493af8969e8be6e6971af6cd4e43b92debcd37`.
Its selection algorithm keeps naturalistic repetitions within one revision,
requires three members with one prompt hash, compares every copied runtime file
against current canonical normalized bytes, and requires at least two joint
passes. Current-source contract reuse across revisions is appropriate when its
payload is unchanged. The collector retains reviewed outcomes from r1, r2 and
r3, including unsuccessful runs, rather than selecting individual passes from
different prompt revisions.

The current three selected owners were independently checked against all twelve
retained raw strict results: approved Luna model, runtime profile, JSON mode,
saved-prompt hash, and integrity before/after digests all matched. This snapshot
is not a declaration that all thirty owners are accepted.

The code audit identified a binding gap to resolve before final acceptance:
the collector trusts the native report's strict result and the manifest's prompt
hash without independently validating raw strict/integrity gates or comparing
the saved prompt to the expected revision case. It also lacks explicit approved
model, runtime profile, exact output-set and exact repetition-ID checks. Bind
those inputs and require repetitions 1, 2 and 3. The supplemental exact-command
sidecar should bind prompt, event-stream and manifest hashes, or be recomputed
at collection, so its boolean cannot refer to different retained bytes. No
observed mismatch was found in the inspected selected runs; these are collector
gating corrections, not grounds to relabel original agent failures.

The r3 recipe states a generic allocation cycle and chooses the first overflow
border using the bundle's existing `textOnFill` decision. Its appended text
contains no categorical hex sequence. It preserves the same independent native
paint, contrast, label, opacity and quantitative-ramp criteria. This is explicit
boundary-recipe coverage, not proof of unconstrained free-form border choice.
Correct palette orders with weak manually chosen borders remain failed outcomes
in earlier cohorts. The protocol now states that limitation explicitly.
