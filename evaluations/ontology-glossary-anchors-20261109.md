# Exact glossary anchors and extraction experiments

## Combining-mark boundaries

The glossary compiler keeps Unicode combining marks with the preceding
non-space character when it locates tokens. It maps token positions
back to the original decoded citation. This preserves the original
code points and the distinction between composed and decomposed
spellings. A prefix that cuts off a combining mark is rejected.

| Check | Result |
| --- | --- |
| Skill tests | 12/12 on Python 3.11 and 3.14 |
| Independent adversarial selections | 39/39 truncated term or value selectors rejected, compared with 4/39 previously |
| Retained V39 single-document regression | 40 source drafts and 60 proposals preserved, plus 20 CLI controls |
| Retained V40 batch regression | 57 CLI invocations and 18 document ledgers preserved |
| Strict GPT-6 Luna low runtime | Both runs retained three distinct source spellings and generated byte-identical ledgers |

The isolated ledger SHA-256 is
`efabd47e7efdc528c50adf343bcd8607e6f25cc485596d6f2d854c1d7cf7f4c4`.
The frozen regressions used characters known to both tested
interpreters. Pin the Python runtime for comparisons that include
characters assigned in different Unicode database versions.
This boundary correction uses the skill's existing tokenizer and
the runtime's general categories for combining marks.

## Luna representation comparison

Three matched development arms used 15 previously exposed cases
with 18 source documents and 30 reviewed proposals. Each arm used
three GPT-6 Luna low calls and the same document framing. The
pointer arm presented document-local token indices and used code to
restore the source spans. All three representations reconstructed
every reference span in a deterministic preflight. A fourth arm
used the same inputs and frame after inspection of the initial
results.

| Actor representation | Compiled documents | Exact documents | Exact cases | Matched proposals |
| --- | ---: | ---: | ---: | ---: |
| Nested quote objects | 14/18 | 9/18 | 8/15 | 19/30 |
| Compact quotes with optional character offsets | 2/18 | 2/18 | 2/15 | 3/30 |
| Token pointers | 18/18 | 6/18 | 6/15 | 12/30 |
| Compact quotes with no actor offsets | 17/18 | 14/18 | 11/15 | 25/30 |

Pointer rows compiled more often and included unsupported wrappers,
such as the definition verb inside the definition value. Exact
scoring preserves multiplicity and counts additional rows in every
compiled document, including documents with other correct definitions.
Four nested-object records used an escaped tab in place of the
physical tab. Inaccurate offsets accounted for the compact carrier's
rejected documents. In the fourth arm the compiler located each
unique quote inside the cited lines. One quoted example still yielded
an incorrect definition and an RFC case lost its aliases. The main
skill keeps the existing quote contract while the fourth arm awaits
evaluation on independent cases.

## Source-window retrieval

The development replay covered 322 annotated term-definition links
from 68 public DEFT documents across seven domains. At about half the
source text budget, BM25 over sentences covered 188 links. Definitional
cues plus an adjacent sentence covered 199. Coverage on the 28
cross-sentence links was 10 and 17 respectively. Replacing the
sentence boundary rules with the spaCy parser reduced full-link
coverage in the matched checks.

Processing every logical block, with a 1,024-character cap and overlap
on oversized blocks, preserved all 322 DEFT links, all 60 retained V39
proposals, and eight reviewed term-and-cue anchors in RFC 9110 and
RFC 9111. This measures whether evidence remains visible to an
extractor. DEFT links are annotated within the supplied source
blocks. Cross-block links and model extraction accuracy are separate
evaluation targets.

[DEFT](https://aclanthology.org/2020.semeval-1.41/) ·
[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html) ·
[RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html)

## Native Harbor carrier comparison

Harbor job `3554b8a7-91bf-4e7b-8776-3c3f45a4dd2c` compared an
aggregate draft with a file per document followed by deterministic
serialization. Both treatments read the same three-source packet
in each of four domain families. There was one independent GPT-6
Luna low attempt per treatment and family, with zero retries.
Seventy-two local verifier controls and 24 Docker controls passed.

Five of the eight attempts incurred strict execution failures after
calling `python` in an image exposing `python3`. Three attempts
remained evaluable and two passed. No family had both treatments
admitted, so the strict run could not measure a matched carrier
advantage. Diagnostic inspection of all retained artifacts found
12/12 parseable and correctly typed documents in each carrier.
The aggregate had 11/12 exact documents under the frozen rubric,
and the files per document had 12/12. A separate replay accepted an
exact source span containing an explicit OpenAPI abbreviation, which
resolved the sole rubric disagreement. The frozen rewards were
preserved.

## One document per inference call

An additional development arm ran the nested-object prompt with
one document in each fresh Luna low call. It reused all 18 documents
and the same runtime bundle. All 18 calls completed with no retries.
The earlier nested-object arm had three calls over groups of documents.

| Metric | Grouped documents | One document per call |
| --- | ---: | ---: |
| Documents with parseable rows | 14/18 | 18/18 |
| Compiled documents | 14/18 | 17/18 |
| Exact documents | 9/18 | 9/18 |
| Matched proposals | 19/30 | 17/30 |
| Unmatched strong proposals after period tolerance | 6 | 10 |

Four documents improved to exact and four lost exactness. The
separate-call arm used 5.68 times the reported tokens. The development
result shows a transport gain alongside a stable document score and
lower proposal coverage. A repeat on independent cases would be
needed to distinguish model variance from changes due to isolation.

A retrospective routing replay kept each grouped output and used
the separately generated draft only for its four documents with
transport failures. It compiled 18/18 documents and matched 12/18
exact documents. The routing decision used transport status and no
reference answers. This result reuses already generated responses
and motivates a prospective trial of selective fallback.
