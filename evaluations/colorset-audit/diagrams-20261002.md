# Diagram and presentation colorset audit — 2026-10-02

This audit covers Mermaid, PlantUML, ECharts animated SVG, Slidev ECharts, Slidev
Anime.js, and Slidev quality audit. Sources and rendered outputs now select exact
colorset1 or colorset2 paints. The runtime default is colorset1; full-color
acceptance galleries deliberately use colorset2 to distinguish multiple
independent categories or demonstration mechanisms. The local tests ran on
2026-10-03 UTC, during the 2026-10-02 client-date session.

The machine-readable companion, [diagrams-20261002.json](diagrams-20261002.json),
lists every supported output route, exact changed skill path, selected modes,
source-fidelity boundary, final isolated run, required outputs, commands,
failures, open gaps, and SHA-256 for all 178 Mermaid/PlantUML published SVGs. The
source baseline was copied independently from the HyperFrames palette contract;
no runtime dependency on another skill was introduced. CSS named-color lookup
tables are input decoding data, not authored palette selections.

image/sprite pixels and declare that boundary in the report; their authored

authored base paints and gradient endpoints. Source logos/images remain narrowly
identified fidelity assets. Data, values, source identities and labels are not
recolored as if they were paint declarations. Custom or imported authored
diagrams that cannot fit the chosen colorset are rejected or reported until
their presentation can be edited.

## Isolated runtime cases and failures

All final tests use the runtime payload profile, one copied read-only skill,
`--no-context-files --no-extensions --no-skills --no-prompt-templates --no-themes`,
exact required paths and strict JSON mode. Summaries require observed
`gpt-5.6-luna`, valid event JSON, zero tool errors, a clean read surface and an
unchanged copied payload. Final run IDs and artifacts are in the companion JSON.
These are targeted contract smoke cases, not a complete release cohort; no
skill was marked done by this audit.

Mermaid, PlantUML and ECharts already have recorded Luna exceptions. Spark was
attempted for each of the three Slidev skills and rejected before any tools:
“The 'gpt-5.3-codex-spark' model is not supported when using Codex with a ChatGPT
account.” The retained runs are `20261002-colorset-slidev-animejs-spark-1`,
`20261002-colorset-slidev-echarts-spark-1`, and
`20261002-colorset-slidev-quality-spark-1`. The root agent must record the three
new Luna exceptions in the backlog. This is an infrastructure limitation rather
than a behavioral pass or failure.

The first Mermaid Luna case failed strict validation: directory-wide styling
scanned copied skill Markdown, modified four references and produced three
tool errors. Exact-file styler support and task-source scoping were promoted
into the skill; the second case passes with an unchanged payload. This failure
is retained as skill-design evidence.

ECharts Luna3 and PlantUML Luna3 retained evaluator invocation failures: their
harness `--expect-output` names did not match the exact prompt paths, even though
the agent produced the requested artifacts. Corrected exact-path reruns passed.
Early deterministic invocations also used an incorrect coverage-manifest
filename, a nonexistent ECharts unit filename and an incorrect animation
stagger parameter; corrected commands passed. Initial browser/static checks
found real named/default/hover/animation paints, XML syntax and contrast defects;
the reported final gates follow their repairs.

Tightened PNG validation also exposed a legacy unit fixture that contained only
a PNG signature rather than an actual image, and the test runner lacked the new
Pillow dependency. The test now writes a real exact-palette PNG and independently
requires rejection after replacing its pixels with an off-palette color even
when `palette_normalized` metadata is absent. All 19 tests pass; malformed PNG
decoding now produces a structured validation finding.

The isolated Slidev quality case is deliberately planning-only. It proves the
palette/CLI/source-boundary contract is understood; the independent full local
deck audits prove actual script execution. It cannot be presented as an
isolated full-deck acceptance pass. No fresh PDF, GIF or video encode was created
for the Slidev decks in this pass; their authored source and HTML runtime are
verified, and downstream raster/compression pixels retain the stated scope.
