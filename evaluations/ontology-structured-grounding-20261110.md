# Executable grounding for structured evidence

The earlier OpenSearch and n8n study separated documentary rules,
caller configuration, and runtime or implementation evidence.
It improved graph agreement, but a separate local entailment model
still accepted an implementation claim using a record for a
different endpoint. This study tests a prospective Terraform and
AWS family and moves exact resource and invocation matching into
code for a second comparison.
[Prior authority projection and review evaluation](ontology-authority-projection-20261110.md)

## Prospective Terraform and AWS transfer

The frozen fixture contains 11 decisions from ten scenarios with
two exact upstream documentation snapshots and synthetic plan,
applied mapping, and invocation captures. The task distinguishes
a known declaration in a plan from a deployed setting and from
an observed mixed-success handler response. It checks the exact
resource, release, deployment, request, and failure identifiers.
The reference rubric and all 24 source and verifier controls were
replayed before model calls. Both reference carriers yielded the
same three asserted triples.
[Terraform provider mapping reference](https://github.com/hashicorp/terraform-provider-aws/blob/92b670b8b4714cca75fa802c0ec0689b62b0c10d/website/docs/r/lambda_event_source_mapping.html.markdown#L215) ·
[Pinned AWS Lambda response guidance](https://github.com/awsdocs/aws-lambda-developer-guide/blob/03f7fcb0b771f031f7cb3aa43e8b18407c00b3a8/doc_source/with-sqs.md#L199-L271)

The two native Harbor arms shared the exact actor packet and
used the sealed holistic and typed carriers. Each ran twice
with GPT-6 Luna low and zero retries. The actual Docker image
passed the frozen CLI and 27 harness controls, and one native
no-inference trial per arm verified the actor commands and byte
transfer of the nested output. The atomic projector reproduced
the prior graph and ledger bytes.

All four live runs retained complete projectable outputs and
the same three-triple reference graph. Both holistic traces passed.
The typed traces were excluded. One agent tried to project an
incomplete review and repaired it after two errors. The other
tried to overwrite an existing output directory and recovered
using a fresh one. The native strict comparison has no typed arm
result. Its retained files are diagnostic.

The two admitted holistic runs had 21/22 correct statuses and
8/22 decisions with the frozen exact evidence sets. One of them
cited every available record per case, which the exact evidence
gate rejected throughout. The two trace-excluded typed files had
21/22 correct statuses, 19/22 joint status and mode-specific
evidence decisions, and 21/22 with the shared flat evidence
diagnostic. The exact criterion and operational exclusions
remain in the original receipts. The identical graphs omit both
refuted and unresolved or conflicting claims, so they do not
establish agreement about the reasons for omitting a claim.

The independent masked review credited 20/22 strict decisions
for both state and decisive evidence, and 19/22 for the complete
reviewed and documented outcome. The strict runs supplied direct
resolution questions in 11/12 open or conflicting cases. The
retained typed diagnostics had 21/22 state and decisive evidence
decisions, 4/12 direct questions, and 8/22 complete outcomes.
They remain separate from the strict cohort. In one strict
output a conflicting invocation was marked refuted, despite
citing both outcomes for the same request. In one diagnostic
output the foreign failed ID was correctly identified and the
proper-subset claim was left open. The supplied complete batch
supports explicit refutation in that case.

## Ground records using exact scopes

The prototype reads only the frozen actor packet to compute
structured findings. It matches the plan by workspace, provider,
plan and exact resource address, the applied mapping by deployment,
and the invocation by request and matching deployment. It keeps
each supporting or refuting witness set with its observation
digest and exact JSON Pointer locators. Evidence for a runtime
claim joins the completion to the complete input batch of that
same invocation before checking the returned identifiers.
Documentary interpretation and review wording are separate.
[Terraform JSON plan format](https://developer.hashicorp.com/terraform/internals/json-format#change-representation) ·
[RFC 6901 JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901) ·
[AWS Lambda response conditions](https://docs.aws.amazon.com/lambda/latest/dg/services-sqs-errorhandling.html#services-sqs-batchfailurereporting-conditions)

| Approach on the same frozen packet | Correct structured requirements | Correct claim states with reference documentary judgments | Same graph as reference |
| --- | ---: | ---: | ---: |
| Read the visible fields directly | 15/23 | 7/11 | No |
| Require the correct authority and scope | 18/23 | 9/11 | No |
| Join the complete batch and validate the returned IDs | 23/23 | 11/11 | Yes |

The first two rows include weaker comparison variants. A nonempty
returned list alone does not establish that it contains a proper
subset of the invocation's input messages. The strongest variant
reproduced the exact witness criteria and graph when combined with
the reference documentary decisions. This mechanical benchmark
does not measure generated documentary choices.

The frozen excerpts use the benchmark convention that an
unmarked invocation input contains the full batch. Outside that
compatibility mode the prototype requires an explicit completeness
marker. An explicitly partial capture takes precedence over the
compatibility option. The independent mutation study detected three
gaps in the initial implementation. An observed empty list, null
list or invalid failure key can refute the mixed-success claim
without the input batch. A malformed or truncated capture still
leaves the state open. The revised implementation passed 35/36
exact witness-shape controls and 36/36 after independent semantic
assessment. The one difference cites the empty return alone,
which suffices to refute the nonempty guard.

The final grounding receipt was byte-identical on Windows Python
3.11 and 3.14 and Ubuntu WSL Python 3.12. A checksum-verified
Terraform 1.13.5 binary also generated a real local plan for
built-in resources. Its five relevant fields covered a known
list, a partially unknown list, an unknown value, an empty list,
and an explicit null. The replay carried the observed value
and unknown-mask shapes through the flag interpreter and retained
their original plan locators. These are local plan shapes, with
no AWS resource creation.
[Terraform 1.13.5 binaries](https://releases.hashicorp.com/terraform/1.13.5/) ·
[Built-in Terraform data resource](https://developer.hashicorp.com/terraform/language/resources/terraform-data)

A separate compiler combines the computed structured findings
with the authored documentary findings and review. The complete
typed path and the grounded path reproduced identical decisions,
RDF and ledger bytes when supplied with the reference inputs.
The compiler rejects submissions that try to author locked slots
or overwrite a retained output directory. Atomic publication
passed in Windows and the Linux Docker filesystem. The WSL
Windows-mounted filesystem rejected the exclusive directory
rename, and the compiler failed closed there. The structured
grounding and Terraform shape replays still ran on that mount.

A read-only replay replaced the structured findings of the two
trace-excluded typed outputs and retained their documentary
decisions and reviews. Correct states rose from 21/22 to 22/22
and exact joint decisions from 19/22 to 21/22. The foreign-ID
case changed from insufficient to refuted. Both graphs stayed
identical to the reference. The replay preserves the original
trace exclusions and does not reevaluate the unchanged reviews.

## Independent Kubernetes runtime experiment

A local Kind cluster ran Kubernetes 1.33.1 at a pinned node
image digest. All three Deployment manifests declared one
replica. The actual API dry run admitted two, and both dry-run
objects remained absent from the store. On actual creation,
the controller recorded the schedulable deployment as available
and the one with an unsatisfiable selector as unavailable.
The API rejected the third manifest's incompatible selector and
template labels. The dry run also removed the forged declaration
status from one manifest. The cluster was removed after retaining
15 exact API bodies.
[Kubernetes API dry-run semantics](https://kubernetes.io/docs/reference/using-api/api-concepts/#dry-run) ·
[Pinned Deployment controller](https://github.com/kubernetes/kubernetes/blob/8adc0f041b8e7ad1d30e29cc59c6ae7a15e19828/pkg/controller/deployment/sync.go#L520-L523)

| Method on three real captures and 14 mutations | Correct decisions | False support | False refutation |
| --- | ---: | ---: | ---: |
| Direct JMESPath selector | 7/17 | 9 | 1 |
| JMESPath with authority, scope and presence checks | 17/17 | 0 | 0 |
| OPA with the equivalent scoped policy | 17/17 | 0 | 0 |
| Python JSON Pointer with the same checks | 17/17 | 0 | 0 |

The scoped implementations require the cluster, namespace, name,
UID, resource version, current generation and a unique Available
condition in the correct observation. The direct selector collapsed
missing and null and could borrow status from another scope.
The independent Python implementation passed 26 controls and
reproduced the same receipt on both Windows versions and WSL Linux.
The target is the controller's condition for that captured snapshot.
Fresh captures have their own IDs and timestamps.
[JMESPath specification](https://jmespath.org/specification.html) ·
[OPA policy language](https://www.openpolicyagent.org/docs/policy-language)
