The original rows are frozen and cloned into the draft. Review captures only
valid names and the current draft revision. A changed edit increments the
revision and invalidates review. Missing review, wrong/stale revision and an
empty reviewed snapshot cannot commit. Committing replaces the result snapshot;
repeated identical commit does not append duplicates. Cancel clears only an
uncommitted review and preserves draft/committed rows.

Native UI uses select/input/confirm with one action per invocation. Menu and
input dismissal leave state unchanged; declined commit preserves review for
retry. It captures the revision before awaiting input or confirmation and
checks authority again before applying the result. Independent interleaving
tests verify stale input cannot overwrite newer edits and stale confirmation
cannot commit an invalidated review. Explicit argument paths bypass UI and
produce readable custom messages with detached state snapshots.

The minimal package declares its actual `extension.ts` entry and loads with
`pi --offline -e ./poc/extension.ts`. It adds no runtime dependency, service,
database, persistent domain store or inference. Optional local registration
is documented accurately and was not performed. Native themes own control
paint; ColorSet 1 is the declared default without claiming exact native pixels.
All authored display copy is English. H1-H10 findings distinguish source,
stub checks and untested keyboard/focus/paint behavior.

## Observed failures and repair recommendations

No generated Pi extension defect was found in this case. Do not invent a
skill repair merely to force every host to produce a failure. The successful
state-authority recipe can be promoted compactly if the root author decides
it improves future authoring: separate immutable input/draft/review/commit,
capture revision before async native dialogs, and revalidate at acceptance.

The generated agent ran `tsc --version` despite the documented no-compiler
runtime path. That optional command was absent, reported as command-not-found,
and explicitly retained in its review. Its multi-command shell call ended
with a successful `pi --version`, so the harness recorded aggregate exit 0
and no flagged tool error. This demonstrates the limit of aggregate shell
error flags; it is not evidence that a compiler was available or a plugin
behavior failed. A future workflow may avoid irrelevant compiler probes or
report their individual outcomes without hiding them behind another command.

The first evaluator selftest set exposed a **validator coverage gap**: removing
name trimming was still rejected on the CLI path because argument parsing
trimmed input, but the checker had not exercised whitespace submitted through
the native input dialog. Its initial result is preserved as
`projects/desktop-plugin-ui/artifacts/plugin-pocs/pi-verifier-selftests/result-v1-coverage-gap.json`.
The evaluator added that real prompt requirement, then the same unchanged
PoC passed 116/116 checks and all five selftests passed. The four injected
defects are wrong revision acceptance, stale-review retention after edit,
menu Escape performing a review, and whitespace UI-name acceptance. No model
rerun or generated-code correction was used. Classification: `validator`.

An evaluator initially looked for an unshipped installed `src/.../types.ts`
path; it corrected its read to shipped `dist/core/extensions/types.d.ts`.
That setup read error is separate from the tested agent trace and is not a
generated-plugin failure.
