# Evidence-classification repair: GPT-6.1 Sol review criteria

Prepared October 25, 2026 before any GPT-6.1 Sol output. This separate
cross-model cohort retains every Luna failure. Semantic standards, prompts
and thresholds are unchanged; only the required evaluator model differs. Freeze
with the root-announced payload and four prompt hashes. This is evaluator
material, not agent input. Preserve all first attempts and previous cohorts;
do not repair tested artifacts or rerun a failed sample under the same subject.

Run contract once, naturalistic three times, boundary once and generalization
three times. Require joint contract 1/1, naturalistic at least 2/3, boundary 1/1
and generalization at least 2/3. Report strict, helper/checker, manual and joint
outcomes separately; no pooling across subjects or earlier tests.

Require all prompt-requested fields, nonempty exact outputs and Boolean false
current-task flags. Strict execution needs the recorded deliberate
`openai-codex/gpt-6.1-sol` exception, valid JSON events, zero tool errors,
prompt-first/focused reads, unchanged runtime payload and no prohibited network,
account, provider, model, app, installation or UI action. Scratch files outside
the read-only skill are allowed. Synthetic lab inputs remain supplied fixtures,
not real-product acceptance or tests newly performed by the agent.

## Classification and evidence coverage

Inspect actual helper use, normalized JSON and derived Markdown, not only the
agent's statement. Require post-write typed-mode checking of both final paths,
inspected `passed:true`, nonzero typed records and final content matching the
checked files. `evidence_ids` must resolve. A record missing required derived
fields, an arbitrary hand-classified table, or checker-only labeling is not a
typed-workflow pass.

Independently reconcile every factual claim used with its scoped record. Use
the new typed contract, not the old requirement that every historical claim
have an observed label. Keep basis, observer, host, surface, version, layer and
execution status accurate; unknown versions must remain explicit. No hidden
row count or preferred ID spelling is imposed. Contract represents all eight
input notes; other cases may select relevant facts, but cannot omit support
for factual claims actually used. Split materially different claims/bases and
do not manufacture execution from supplied statements or static code.

- Source declarations and documentation derive `documented`, not observed
  requests, rendering or callbacks. A source path is not an execution receipt.
- A user report preserves its reported result with automated execution not-run.
  No chart visibility claim upgrades to verified controls or agent screenshots.
- A skipped/not-established test is `untested`; it is not an observed failure.
- Executed checks need a genuine action, expected result, actual result and
  accurate declared outcome. Expected rejection, preserved state and accepted
  Boolean false are passing checks when expectations match. A real unmet save
  expectation is a failed check. No false/null coercion or invented cancellation.
- Conditional prerequisites are not confirmed capabilities. An explicit
  exclusion needs the cited contract's actual exclusion and stays surface-bound.
- The classifier validates declared fields, not factual truth or complete
  coverage. Passing it does not excuse an unsupported assertion in prose.

For boundary, use the actual bundle facts: later trust cleared but model
sign-in remained required; user chose continuation without sign-in; activation
attempt/log termination is not authenticated readiness; the CS1 probe is mixed
MCP/synthetic-browser fixture evidence; transient Codex discovery/binding does
not establish controls. The hypothetical stale-edit sentence has no executed
receipt in this task. Do not invent one.

## Useful recommendations and preserved design contract

Naturalistic must cover requested clients/features with usable mechanisms,
prerequisites, fallback, next checks and realistic state ownership. Keep CLI,
desktop, IDE, MCP Apps, ordinary webviews and canvases distinct. Do not invent
stock-Codex exclusions or a developer-owned-frontend requirement. MCP App CSP
field names cannot configure ordinary VS Code webviews. Account/controller
gates are not product exclusions. Preserve the no-Copilot-sign-in choice.

For naturalistic/generalization, inspect all H1-H10 canonical IDs/short labels
and concrete checks, English authored copy including Explain/export scope,
requested identifiers, and separate authored versus host-owned paint. CS1 is
the naturalistic default; generalization explicitly requests CS2. Validate
claimed paths/values against the frozen asset and actual design-helper use;
independently recompute any reported contrast (unrounded tolerance 1e-9) and
inspect role thresholds. No unsafe sole focus or ordinary error-text pairing
may be presented as accepted. A heuristic review is not a user study.

Contract/boundary are diagnostic tasks, not renderer designs; do not impose
unrequested layouts, heuristics, palettes or numeric claims. Voluntarily added
claims must still be correct. All authored prose is English. Exact primary
URLs in either output must match the bundle catalog; supplied fixture source
locators are valid task evidence without fabricated public URLs.
