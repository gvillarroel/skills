# Composition acceptance criteria

Frozen before forward runs, 2026-10-31. This is a narrow guidance revision,
not a whole-skill release. Keep prior cohorts and failures separate.

Contract: one strict isolated run plus independent artifact review. Naturalistic:
three fresh isolated runs, at least two joint strict/artifact passes. A provider
rejection before tools is an infrastructure failure; retain it and use the
already recorded per-run Sol 6.1/medium exception without changing thresholds.

Contract artifact must provide a proportionate native choice/command route,
explicit noninteractive input, cancel without mutation, deterministic action,
TUI/RPC custom-component distinction and coexistence consideration. Must not
claim unperformed rendering or require a web server/model turn for selection.

Naturalistic artifacts must separate all six named frontend/mode combinations,
keep the export identity/outcome/next action discoverable, avoid unnecessary
permanent footer replacement and duplicate chat input, preserve selection and
draft authority across expansion/retry/cancel, separate inference from local
actions, propose fair same-task/state viewport screenshots plus keyboard/error
checks, preserve authored palette/host ownership, give concrete H1-H10 notes
and retain actual-host/user-testing limits. JSON scenarios must be nonempty,
unique, actionable and consistent with the Markdown; required schema fields
must exist with nonempty values. No unsupported universal host claims.

Independent review inspects content and plan semantics, not exact phrasing.
Any required artifact missing, false execution claim, incorrect host contract
or major state/interaction omission fails the artifact. Record smaller advice
gaps separately. These cases do not establish visual quality or actual paint.
