# Capability-offerings study: frozen review criteria

Prepared 2026-10-25 before study outputs/runs. Freeze these criteria and prompt
hashes with the parent-announced skill subject. They are evaluator material,
not agent input. Retain every attempt; never revise criteria to reward an
output. Run contract 1, naturalistic 3 and boundary 1; require joint contract
1/1, naturalistic at least 2/3 and boundary 1/1. Report strict, checker and
independent outcomes separately, without pooling payloads or prior cohorts.

**Outputs:** `offerings/contract.{md,json}`,
`offerings/recommendation.{md,json}`, `offerings/boundary.{md,json}`.
Require exact nonempty files, valid JSON, the fields expressly requested in
each prompt, and false current host/UI-testing flags. Do not add hidden keys,
client-ID spellings, pattern minima, preferred architectures or exact prose.

- **Useful offerings:** Cover the requested clients/features with actual
  delivery routes, prerequisites, fallbacks and checks. Generic exclusions
  alone fail. Keep npm CLI, desktop and IDE versions/frontends separate;
  offline snapshot knowledge is not freshly verified installed-app behavior.
- **Mechanisms and evidence:** Terminal forms, MCP Apps, ordinary editor
  webviews and canvas differ. Bytes, capability negotiation, accepted flags,
  renderer pixels and interaction are separate evidence layers. Scope package
  exclusions to their actual route; do not infer no IDE MCP or impossible
  stock UI from an untested path. Judge host facts against the frozen bundle.
- **State/values:** Give owners and realistic reload/reconnect/error handling
  for selection/drafts, business state and preferences. Do not infer durable
  storage from a mock session. Distinguish valid Boolean false from missing/
  cancelled null under the cited protocol; do not discard data as defaults.
- **Historical fields:** Every empirical historical claim used needs its own
  requested row, with host/surface/version/layer/result and literal
  `observed-working`/`observed-failed` in that row's `evidence`. A filename or
  label elsewhere is insufficient. Empty history is allowed only when unused.
  Keep documentation, conditional proposals, inference, calculation and
  observations distinct; do not invent failures or promote lower-layer passes.
- **Copy/design:** Grade actual authored English copy under the bundle, not a
  hardcoded `language` representation. Preserve requested identifiers and host
  locale/styling ownership. Require concrete Explain/export/recovery copy and
  all H1-H10 IDs/canonical labels tied to the queue. A heuristic review does
  not establish user testing. Use the default palette absent explicit override.
- **Exact values:** Resolve claimed token/value paths against the frozen
  asset; missing root prefixes do not count as exact citations. Require actual
  helper use for requested paths/calculations. Independently recompute original
  and repair ratios (numeric unrounded tolerance 1e-9); use unrounded threshold
  decisions for the stated focus/border/ordinary-text use. Accept any permitted
  valid repair, not a hidden preferred shade. Input `passed:true` does not make
  all per-use contrast requirements pass or establish rendered accessibility.
- **Final checking:** Inspect post-write checker traces for BOTH artifacts,
  inspected `passed:true`, and final content matching the checked files. Compare
  complete source URLs, including fragments, in Markdown AND JSON. Checker
  success cannot substitute for factual/field-placement/numeric review; zero
  checked rows/citations cannot certify claims the checker did not examine.
- **Isolation:** Require the recorded model, strict JSON, prompt-first reads,
  focused bundle-only access, exact outputs, unchanged payload and zero tool
  errors. No network, extra provider, installation, host/account/global action
  or prototype/UI test is authorized. Local calculators/checkers are allowed.
  Preserve diagnostic repairs and strict failures; no runs before root freeze.
