# Compose Synchronized SVG Evaluation — 2026-07-11 to 2026-07-12

## Scope and release rule

This evaluation tests whether an isolated `gpt-5.3-codex-spark` agent can turn a compact domain brief into one final standalone SVG whose complementary modules share canonical state, coordinated focus, explicit cross-module relationships, and one optional master timeline.

Release requires one frozen runtime payload and four gates:

- one strict contract smoke pass with all seven exact outputs;
- at least two complete passes from three compensation repetitions;
- at least two complete passes from three cloudburst repetitions;
- at least two complete passes from three edge-load repetitions.

A complete repetition requires strict event JSON, the observed Spark model, zero tool errors, seven exact artifacts, both report fields `ok=true`, unchanged copied skill payload, a clean read surface, independent static and browser passes, and manual visual plus domain-semantic approval. Earlier runs remain failure evidence and never become release passes retroactively.

## Patterns promoted into the skill

- Select modules from distinct viewer questions and record both the winning asset rationale and nearest rejected alternative.
- Use one declared armature and reading order rather than an equal-card dashboard or an unstructured collage.
- Treat top-level focus groups, the canonical DAG, revision counter, and master timeline as sole authorities.
- Compose from the compact brief; never patch the monolithic SVG during normal generation.
- Run the advisory preflight immediately after each complete brief write. Expected syntax or semantic findings return `ok: false` without a tool error; rewrite the whole brief and call the publishing compiler only after `ok: true`.
- Reject duplicate JSON keys and require every declared source concept to be visibly bound somewhere in the composition.
- Use ordinary bars only for same-unit values that remain nonnegative over their full legal envelopes. Require one shared zero baseline, domain, range, and pixels-per-unit slope.
- Keep stack parts disjoint, nonnegative, reconciled to one declared total, and in the same unit. An explicit `stackTotal` disables label-based inference of scaled aliases.
- Prefix recurring annual, monthly, weekly, daily, or hourly measures in exact generated tables so equal base labels remain distinguishable.
- Keep generated flows in one unit with one source first and mutually exclusive signed branches whose algebraic sum equals the source in every audited state. Use a network or table for nonconserving values.
- Infer exact additive and residual partition contracts from flows, networks, and tables. Reject any derived rollup that adds a conserved whole to one of its own branches; permit `whole - branches` as a reconciliation identity.
- State part/subtotal/total hierarchy explicitly in visible claims. Use a table or arithmetic bridge for static equality or unit conversion, and reserve line/timeline assets for genuine ordered progressions with a meaningful axis.
- Require every selected ancestor/descendant pair in a network to include the complete direct-dependency bridge needed by its claim.
- Reject unsupported generic asset names instead of rendering anonymous fallback blocks; every compact asset selects one of the eight semantic families.
- Lay out eight modules as balanced 4+4 rows rather than 3+5, preserving usable widths for labels and arithmetic marks.
- When a task requires a forward chain, keep all required facets in one connected relationship component and close feedback into the same spine. Support feedback through the DAG or an explicit trigger/response phase story, and distinguish required response from deployed response.
- Check scenario isolation at module level: an allegedly unchanged representation may not bind a downstream value that changes.
- Update flow source headers, branch labels, accessible values, and geometry from the same canonical snapshot; stale visible text is a blocking synchronization failure.
- Decide flow zero and direction from exact raw canonical values after negative-zero normalization, not transformed pixels. Preserve finite tiny values with round-trip serialization and adaptive scientific text when declared rounding would otherwise display zero.
- Mirror computation order and `Math.round` half-tie behavior across Python and JavaScript; compare canonical snapshots and bound values exactly after normalizing negative zero.
- Base flow reconciliation tolerance on finite operation scale without summing magnitudes into overflow; non-finite totals, differences, or tolerances are blocking.
- Keep waterfall endpoints nonnegative, deductions sign-stable, and all steps on one zero-anchored absolute scale with exact opening-minus-deductions reconciliation.
- Allocate unique relationship lanes before drawing, preserve at least 15 user-space pixels between incident markers at the painted edge, and never collapse lanes with a later clamp.
- Let an opaque cartographic plaque exempt a focus-label crossing only when Chromium proves complete measured coverage and correct DOM paint order.
- Validate the initial state, every scenario, legal source perturbations, exact representable zero-flow boundaries—including interior roots with equal-sign endpoints—focus states, sampled phases, reduced motion, and the literal script-free fallback.
- Derive phase progress independently from requested time and phase bounds; require snapshot, root attribute, label, and pulses to agree.
- Keep focus-region layers pointer-transparent, prove the timeline hit target with `elementFromPoint`, and use revision progress rather than wall-clock monotonicity across a loop seam.
- Supervise the Chromium worker in an isolated process group with finite bounded timeouts, one internal retry, UTF-8 diagnostics, cancellation cleanup, and descendant reaping.
