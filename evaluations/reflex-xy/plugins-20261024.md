# Reflex XY integration release — 2026-10-24

## Subject and scope

This project adapts the existing `reflex-xy` skill to three actual extension
interfaces: Claude Code Mods, ordinary Claude Desktop MCPB/MCP Apps, and
ChatGPT custom MCP connections. Canonical source is
`projects/reflex-xy-plugins/`; generated releases and raw execution evidence are
under its ignored `artifacts/` directory. The [installation guide](../../docs/reflex-xy-plugins.md)
describes the host-specific setup and limits.

The canonical skill was not modified. Its existing isolated Pi cohorts and
`validating` status remain unchanged; protocol and adapter tests do not replace
those cohorts. Packaging copies the 18-file runtime snapshot and excludes
`assets/examples/`. Claude Code uses one copy at `skills/reflex-xy`; the MCP
packages use `runtime/skill/reflex-xy`. All 19 local Markdown links resolve inside
each copied runtime bundle.

The Python bridge uses native **XY 0.0.8**, its canonical colorset helper and
narrow SVG compatibility repair. It provides 36 presets, 28 factories, 22 marks,
23 components, a bounded generic JSON grammar and both palettes. Preset defaults
are labelled synthetic; supplied data is preserved or rejected with an explicit
error. It never evaluates submitted code or loads submitted filesystem/network
paths. HTML is a browser-interactive snapshot, not a live Python callback host.

## Retained corrections

Initial presets passed full categorical palettes where XY requires exactly one
color per series/stage/slice. Other failures exposed radar self-closing, an
unsupported wind-rose `colors` keyword, `type_='log'` axis syntax and the native
`reveal` animation mode. The independent SVG checker initially mishandled
transparent eight-digit hex. All first reports are retained.

Native Claude tests found that Desktop `Link` rejects `file:` and clipboard
copying takes `ui.copy({text})`. Buttons now use fixed OS opener argument vectors
only after user action; Python source is copied rather than OS-opened. Preview
state is scoped by session and cleared on session end.

The first component browser build used replacement syntax that interpreted
JavaScript dollar expressions; functional replacement fixes it. Later manual
mobile review found a cropped native canvas despite no outer overflow. The
component establishes visible iframe layout before XY initializes, and the
acceptance checks now verify the inner canvas as well as the outer widget.

OpenAI's exact authentication documentation shows that ChatGPT cannot present
an arbitrary static API key. Instructions now use **No authentication** only
for the non-sensitive demonstration, with explicit anonymous public-bind opt-in.
Private ChatGPT use requires an operator-supplied supported OAuth gateway; this
prototype does not implement an OAuth authorization server. Static bearer
support remains available to compatible MCP clients.

## Commands

From the repository root, build the Node sources first:

```powershell
Push-Location projects/reflex-xy-plugins/chatgpt
npm ci --ignore-scripts
npm run check
npm test
npm run build
npm run test:browser
npm run test:bundled
Pop-Location
uv run --script projects/reflex-xy-plugins/scripts/build_plugins.py --desktop --output-dir projects/reflex-xy-plugins/artifacts/releases/0.1.0
```

Use a fresh release directory for another run. Independent representative
commands, full preset selection, native Claude commands and evidence retention
are recorded in [the project acceptance contract](../../projects/reflex-xy-plugins/notes/validation-plan.md)
and [Claude sources](../../projects/reflex-xy-plugins/notes/claude-sources.md).
The final matrix uses the extracted package's renderer and skill paths, never
the canonical skill as a fallback. Official docs and installed schemas were
read before implementing host-specific contracts.

## Acceptance boundaries

Actual installation and invocation inside signed-in **ChatGPT** or ordinary
**Claude Desktop chat** remain **not tested**. The packages, native Code engine,
real transports, native renderer and protocol-host component have been tested;
this does not establish account-level installation or native app painting.
No user configuration outside the repository was changed, and no public
endpoint or account connection was created.

ChatGPT needs an account permitted to add custom MCP servers and a reachable
HTTPS origin serving both MCP and native assets. Secure MCP Tunnel supports
private MCP calls but does not automatically proxy separate HTML/download
routes; this release's complete widget uses a reachable asset origin. The local
Claude Desktop MCPB uses stdio and a loopback artifact port, omits `ui.domain`
as required and needs `uv` available to its host process. macOS native paint,
Linux Code opening and actual OS opener dispatch remain untested.

MCP capability links expire after 20 minutes or restart. Cache limits are per
server process; expired records are pruned on a later render, and files left by
a stopped process may remain for operator cleanup. The prototype has no durable
multi-user ownership store. Data callbacks, custom registered Python plugins
and future live streams are intentionally outside the bounded JSON tool.

The environment's npm age cutoff rejected newer Claude/MCP SDK releases and
fixed transitive `body-parser`/`fast-uri` versions. It was not bypassed. The
server uses `node:http` and its own bounded parser, rejects compression and does
not invoke the Express/body-parser request path. The audit findings remain;
recheck dependencies when allowed updates become available. Bundled dependencies
ship `THIRD-PARTY-NOTICES.txt` (25,928 bytes).
