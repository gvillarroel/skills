# Video Style Extension: **Metro Minimal Tonal Motion**

This visual style keeps the same core language: **flat surfaces, large modular blocks, background-based separation, simple geometry, and clean composition**.

For video, the scene should not be treated as a fixed screen or slide. Instead, it should be designed as a **large navigable visual object**: a megacanvas made of subsections that the camera explores through zooms, pans, reveals, and block-based transitions.

No space should be reserved for titles, subtitles, captions, or editorial text. These will be added later in post-production. The composition should focus only on the visual objects themselves: data, charts, diagrams, graphs, tables, modular blocks, and animated structures.

No rounded borders!

---

# 1. General video principle

The video should feel like a **large modular map**.

Instead of creating isolated scenes, build a wide visual composition with multiple zones:

```text
[ Zone A: visual summary ]

[ Zone B: main chart ]

[ Zone C: table or matrix ]

[ Zone D: graph / process ]

[ Zone E: Metro-style blocks ]

[ Zone F: Masonry data/concept layout ]
```

The camera reveals these zones through:

* zoom in,
* zoom out,
* horizontal pan,
* vertical pan,
* diagonal movement,
* movement into a subsection,
* movement back to a full overview,
* block expansion transitions.

The result should feel continuous, not like a sequence of disconnected slides.

---

# 2. Do not reserve space for titles or subtitles

Important rule:

> Do not design empty areas for titles, subtitles, captions, or external editorial text.

This means:

* no empty top bands for future titles;
* no intro text boxes;
* no reserved lower area for subtitles;
* no layouts centered around future narration text;
* no composition that depends on external copy.

The scene must feel visually complete without those elements.

Allowed text should only be functional text that belongs to the visual object itself:

* chart labels,
* values,
* node names,
* states,
* categories,
* axes,
* minimal legends,
* table data,
* process labels.

---

# 3. Large-object composition

For video, the design should be planned as a **megacanvas**.

Each shot can be a section inside a much larger object. The camera does not need to cut immediately; it can explore.

Example:

```text
Full overview:
┌─────────────────────────────────────────────┐
│ KPI blocks      Main chart        Graph     │
│                                             │
│ Masonry concepts       Comparison table     │
│                                             │
│ Process flow           Heatmap / matrix     │
└─────────────────────────────────────────────┘
```

The video can then move like this:

```text
zoom in → main chart
pan → graph
zoom out → full structure
zoom in → table
expanding block → new scene
```

This creates visual continuity and avoids abrupt scene changes.

---

# 4. Layout types for video

## 4.1. Tonal surface layout

This is the base mode.

The scene is divided into large background surfaces, each with a clear function.

Best for:

* dashboards,
* technical explanations,
* concept maps,
* software architecture,
* data analysis,
* process diagrams.

The camera can move between surfaces as if exploring a clean visual plan.

---

## 4.2. Metro layout

Use this when an element needs stronger visual presence.

Characteristics:

* large blocks,
* solid rectangles,
* visible data,
* strong hierarchy,
* direct composition,
* few elements per block.

Best for:

* key metrics,
* important points,
* decisions,
* states,
* visual highlights,
* product modules.

In video, Metro blocks can appear, expand, slide, or become scene transitions.

---

## 4.3. Masonry layout

**Masonry** must be included as a valid layout option.

It is a composition of blocks with different sizes that fit together like bricks, without using a rigid uniform grid.

It should feel ordered, not chaotic.

```text
┌────────────┐ ┌──────┐ ┌──────────────┐
│            │ │      │ │              │
│  Block A   │ │  B   │ │   Block C    │
│            │ └──────┘ │              │
└────────────┘ ┌────────┴──────┐       │
┌──────┐       │   Block D     │       │
│  E   │       │               │       │
└──────┘       └───────────────┘
```

Masonry works well for:

* multiple concepts,
* data cards,
* fragments of information,
* mini charts,
* icons with metrics,
* insights,
* categories,
* features,
* product modules,
* non-linear timelines,
* visual collections.

---

# 5. Masonry animation

In Masonry layouts, blocks can appear as if a modular wall is being built.

Each block should enter from an empty area and smoothly fit into its final position.

The animation can combine:

* fade in,
* directional movement,
* soft deceleration,
* precise final alignment,
* staggered reveal,
* subtle adjustment of nearby blocks when needed.

The motion should feel like:

> A visual brick entering an empty space and snapping cleanly into a modular composition.

---

## 5.1. Masonry construction directions

The Masonry layout can be built using different reveal patterns.

### Top to bottom

Useful for hierarchy or reading order.

```text
top area first
then middle area
then lower area
```

### Bottom to top

Useful for construction, growth, or accumulation.

```text
base → structure → result
```

### Left to right

Useful for progressive storytelling.

```text
origin → process → result
```

### Right to left

Useful for reverse analysis, cause tracing, or backtracking.

```text
result → explanation → origin
```

### Radial

Useful when there is a central concept.

```text
center → surrounding blocks
```

or:

```text
outer blocks → center
```

### By columns

Useful for comparison.

```text
category A
category B
category C
```

### By groups

Useful for related concepts.

```text
group 1 appears
group 2 appears
group 3 appears
```

### Controlled random

Useful for a more dynamic feel, as long as the final result remains clean.

The blocks should not appear chaotically. The sequence must feel intentional.

# 6. Main transition types

## 6.1. Zoom in to subsection

The camera moves closer to a specific area of the megacanvas.

Best for:

* entering a chart,
* reading a table,
* inspecting a node,
* showing a highlighted block,
* moving from overview to detail.

The transition should end with the subsection perfectly framed.

---

## 6.2. Zoom out to full system

The camera pulls back to reveal context.

Best for:

* showing how one part belongs to a larger system;
* closing an explanation;
* connecting several metrics;
* revealing the full architecture;
* moving from detail back to overview.

---

## 6.3. Horizontal or vertical pan

The camera moves to another section without cutting.

Best for:

* comparing two zones,
* moving through a process,
* following a timeline,
* moving from one chart to another,
* exploring a wide dashboard.

The motion should be clean, stable, and intentional.

---

## 6.4. Diagonal movement

Useful for more dynamic compositions.

Use it moderately, especially when the goal is to create a sense of exploration.

---

## 6.5. Expanding block transition

A block can grow until it covers the entire frame.

Then, when it moves, contracts, or disappears, it reveals a new scene.

Sequence:

```text
selected block
→ expands
→ covers the full frame
→ content changes behind it
→ block moves or shrinks
→ new scene is revealed
```

This works especially well with the Metro influence, because a tile becomes the transition device.

---

## 6.6. Surface wipe transition

A flat surface can slide across the frame like a clean curtain.

Best for:

* topic changes,
* section changes,
* scene transitions,
* chapter separation.

It should remain flat and graphic, with no volumetric effects.

---

## 6.7. Tile morph

A block changes size, proportion, or position until it becomes another module.

Examples:

```text
KPI card → full chart
mini table → large table
node → expanded graph
summary block → detailed section
```

The source and destination should feel visually connected.

---

## 6.8. Masked reframing

A section can behave like a window into another view.

Example:

```text
a rectangular block opens
→ a chart appears inside
→ the camera enters the chart
```

This should feel like navigation inside the same visual system.

---

# 7. Chart animation for video

Charts should animate functionally, not decoratively.

## 7.1. Line charts

Recommended animation:

* axis appears subtly;
* line draws from left to right;
* final point appears with emphasis;
* direct labels appear after the line;
* secondary series appear in a muted way.

The camera can follow the line as a transition to another block.

---

## 7.2. Bar charts

Recommended animation:

* bars grow from the baseline;
* labels appear at the end;
* highlighted bar enters with stronger presence;
* secondary bars can appear in cascade.

A bar can also expand to cover the frame and transition into a new scene.

---

## 7.3. Area charts

Recommended animation:

* top line draws first;
* area fades in after;
* key points reveal in sequence.

Avoid making the area feel too visually heavy.

---

## 7.4. Donut / limited pie charts

Recommended animation:

* main segment appears first;
* secondary segments complete the shape;
* central value appears last.

Use only with a small number of categories.

---

## 7.5. Heatmaps

Recommended animation:

* cells appear by row, column, or group;
* intensity reveals gradually;
* important cell is highlighted at the end.

This can combine very well with Masonry motion.

---

## 7.6. Scatter plots

Recommended animation:

* points enter by group;
* main cluster becomes emphasized;
* selected point gets a label;
* the rest becomes visually muted.

Avoid making all points appear at the same time when the chart is dense.

---

## 7.7. Sankey / flow diagrams

Recommended animation:

* nodes appear first;
* flows draw afterward;
* main route gains emphasis;
* secondary routes remain subtle.

The camera can follow the flow as a transition path.

---

## 7.8. Treemaps

Treemaps are highly compatible with this style.

Recommended animation:

* main container appears first;
* then it subdivides into blocks;
* main blocks receive labels;
* one cell can expand to reveal detail.

A treemap can transition naturally into a Masonry or Metro layout.

---

# 8. Graph animation

## 8.1. Network graphs

Recommended animation:

* central node appears first;
* related nodes enter around it;
* links draw after nodes;
* clusters are grouped by background surfaces;
* selection mutes unrelated elements.

Avoid revealing all nodes at once if the graph is complex.

---

## 8.2. Directed graphs

Recommended animation:

* levels appear in order;
* arrows draw according to direction;
* critical path is emphasized;
* secondary nodes become muted.

The camera can follow the graph direction.

---

## 8.3. Trees

Recommended animation:

* root appears first;
* branches unfold by level;
* leaves appear with fade;
* selected group expands.

The natural transition is a zoom into a branch.

---

## 8.4. Process flows

Recommended animation:

* steps appear sequentially;
* connectors draw between steps;
* decision points appear with a short pause;
* final result becomes a stronger Metro-style block.

---

# 9. Table animation

Tables should appear cleanly and remain readable.

## 9.1. Table entrance

Options:

* rows appear in cascade;
* columns appear by group;
* header appears first;
* key cells receive emphasis;
* totals appear last.

Do not animate every cell individually in large tables. Use groups.

---

## 9.2. Visual scroll

For long tables, avoid excessive zooming into each row.

Prefer:

* smooth vertical camera movement;
* fixed highlighted section;
* muted secondary rows;
* visual summary on the side;
* zoom toward an important cell.

---

## 9.3. Table to chart transformation

A table can transform into a chart.

Example:

```text
numeric column
→ horizontal bars
→ full chart
```

Or:

```text
selected rows
→ KPI cards
→ Masonry insight layout
```

---

# 10. Visual rhythm

The video should feel clear, not rushed.

Recommended rhythm:

```text
brief entrance
→ readable pause
→ camera movement
→ reveal
→ pause
→ transition
```

Each object should remain visible long enough to be understood.

Avoid:

* too many transitions in a row;
* constant motion without pauses;
* aggressive zooms;
* unnecessary rotations;
* too many simultaneous animations;
* animation without hierarchy.

---

# 11. Visual depth without 3D

Even with camera movement, the style must remain flat.

Avoid:

* exaggerated 3D perspective;
* realistic shadows;
* decorative cinematic depth;
* floating objects without structure;
* reflections or artificial lighting.

Depth should come from:

* scale,
* zoom,
* framing,
* hierarchy,
* surfaces,
* progressive reveal,
* spatial grouping.

---

# 12. SVG usage for video

SVGs should be built with animation in mind.

Recommendations:

* separate elements into logical groups;
* name layers or groups by function;
* avoid converting everything into one single path;
* keep text editable when possible;
* use simple shapes;
* use masks for reveals;
* use clipping for transitions;
* use animatable strokes;
* prepare blocks so they scale cleanly.

Ideal structure:

```text
svg
 ├─ background-surfaces
 ├─ section-groups
 ├─ charts
 ├─ graph-nodes
 ├─ graph-edges
 ├─ tables
 ├─ masonry-blocks
 ├─ metro-tiles
 └─ transition-shapes
```

---

# 13. Masonry in SVG/video

Masonry blocks should be independently animatable.

Each block should have:

* its own group;
* its own background;
* grouped internal content;
* defined final position;
* possible entry point;
* reveal order;
* normal state;
* highlighted state;
* muted state.

Example:

```text
masonry-block-01
masonry-block-02
masonry-block-03
masonry-block-04
```

Each block may enter from:

* top,
* bottom,
* left,
* right,
* center,
* outside the frame,
* a nearby empty space,
* behind another block,
* reduced scale,
* zero opacity.

The motion should feel like fitting into place, not bouncing.

---

# 14. Masonry block transitions

A Masonry block can become a narrative device.

## Block fits in

```text
block enters
→ finds its space
→ aligns
→ internal content appears
```

## Block pushes

```text
block enters
→ moves nearby blocks
→ new composition stabilizes
```

## Block reveals

```text
empty block enters
→ fills with chart, value, or icon
```

## Block expands

```text
selected block
→ grows
→ occupies the full screen
→ transforms into a new scene
```

## Block collapses

```text
full scene
→ shrinks into a block
→ block integrates into a larger Masonry layout
```

---

# 15. Coherence across UI, charts, graphs, tables, and video

Everything should share the same visual language:

* surfaces as separation;
* flat shapes;
* rectangular blocks;
* clean grids;
* functional typography;
* color by role;
* minimal ornament;
* purposeful motion;
* emphasis only when needed;
* Metro as the high-impact mode;
* Masonry as the flexible modular composition mode.

The camera should act as a guide, not as a decorative effect.

---

# 16. Reusable video prompt

```text
Create a visual composition in Metro Minimal Tonal Motion style. Use a flat, modular, clean aesthetic based on background surfaces to separate sections. Avoid decorative shadows, heavy borders, bevels, textures, ornamental gradients, and unnecessary decoration. Use color only by role: primary color, secondary color, emphasis color, surface color, state color, and data colors.

Do not reserve space for titles, subtitles, captions, or external editorial text; those will be added later in post-production. Include only functional text that belongs to the visual object itself, such as labels, values, axes, node names, states, or data.

Plan the scene as a large visual object or megacanvas with multiple subsections: dashboards, charts, graphs, tables, diagrams, Metro blocks, and Masonry compositions. The presentation should happen through camera movement: zoom in, zoom out, horizontal pan, vertical pan, or movement toward another subsection.

Include Masonry as a layout option: rectangular blocks of different sizes that fit together like bricks inside a modular composition. Blocks may appear with fade in and movement, entering from empty spaces until they fit into their final position. The construction may happen top to bottom, bottom to top, left to right, right to left, radially, by columns, by groups, or through controlled randomness.

Allow transitions where a block increases in size until it covers the whole frame and, when it moves, shrinks, or disappears, reveals a new scene. Also allow transitions through zooming into subsections, zooming out to an overview, panning between zones, expanding tiles, transforming a table into a chart, transforming a node into a graph, and using blocks as masks or reveal surfaces.

SVGs, charts, graphs, and tables must be built with flat shapes, simple lines, direct labels, minimal legends, discreet axes, background-based grouping, and controlled emphasis. Each element should be animatable by logical group: surfaces, blocks, data series, nodes, links, rows, columns, and Masonry pieces.
```

---

# 17. Short style definition

> For video, this style behaves like a giant visual model: flat, modular, and navigable. The camera explores subsections through zoom and movement. Metro blocks provide emphasis and strong transitions. Masonry provides flexible modular composition where pieces appear, move, and fit like bricks. No space is reserved for titles or subtitles; the design focuses on visual objects, data, and animated structures.
