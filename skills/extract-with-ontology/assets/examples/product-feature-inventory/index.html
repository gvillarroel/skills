GitHub Copilot code review

The review is generated by Copilot and the documented mechanism uses agentic capabilities and model/token usage. Automatic review is a configured mode of the same reviewer.

Each time {% data variables.product.prodname_copilot_short %} reviews a pull request or reviews code in your IDE, the interaction consumes {% data variables.product.prodname_ai_credits_short %}. The amount depends on the model used and the number of tokens processed.

Copilot cloud agent

The agent is defined as an AI system. The scoped GitHub cloud workflow delegates repository research, changes and a pull request to it.

## What is an agent? An agent is an AI system that can complete a goal on your behalf. Unlike an assistant that only returns a response, an agent can plan a task, use tools to take action, inspect the results, and adjust its approach. For example, when you ask an agent to fix a bug, it can search a repository, identify the relevant files, edit the code, run tests, and revise its changes in response to test failures. The tools and environments available to an agent depend on where you use it.

Human pull request reviews

The documented actor in this scoped review mode is a person. It remains distinct from an approving review submitted by Copilot under an optional policy.

Pull request reviews let people comment on changes, suggest improvements, and approve or request changes before code is merged. Anyone with read access can review and comment on proposed changes, helping teams maintain code quality and share knowledge.

Pull request auto-merge

The stated behavior is a rule-triggered merge. Related Copilot blocker remediation may run first without changing this merge rule.

{% data variables.copilot.agent_merge %} fixes blockers, while auto-merge merges a pull request after all required reviews and status checks pass. Enabling {% data variables.copilot.agent_merge %} does not enable auto-merge.

Branch protection rules

The documented rules enforce selected push, merge, force-push or delete conditions. They can gate on separate features without inheriting how those features produce results.

By default, each branch protection rule disables force pushes to the matching branches and prevents the matching branches from being deleted. You can optionally disable these restrictions and enable additional branch protection settings.

Dependabot security updates

The source specifies the vulnerable-dependency trigger, compatibility against the dependency graph and the minimum patched version. The neighboring AI-agent assignment workflow is out of this capability's scope.

{% data variables.product.prodname_dependabot %} checks whether it's possible to upgrade the vulnerable dependency to a fixed version without disrupting the dependency graph for the repository. Then {% data variables.product.prodname_dependabot %} raises a pull request to update the dependency to the minimum version that includes the patch and links the pull request to the {% data variables.product.prodname_dependabot %} alert, or reports an error on the alert. For more information, see [AUTOTITLE](/code-security/reference/supply-chain-security/troubleshoot-dependabot/dependabot-errors).

Dependabot version updates

The documented mechanism reads configured manifests and compares versions. Keeping versions current is distinct from patching known vulnerable dependencies.

For each action in the file, {% data variables.product.prodname_dependabot %} checks the action's reference (typically a version number or commit identifier associated with the action) against the latest version. If a more recent version of the action is available, {% data variables.product.prodname_dependabot %} will send you a pull request that updates the reference in the workflow file to the latest version.
