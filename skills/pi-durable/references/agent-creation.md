# Create an independent agent from Pi

Use this workflow when a Pi user wants a new durable agent with a chosen base folder. For installation, connection discovery and existing-agent commands, read [Pi console extension](pi-extension.md). The generated console carries its own service resources; it needs no skill checkout after generation.

In terminal mode, `/durable` opens an agent manager with a visible **Create new agent (choose base folder)** action. `/durable-chat` offers the same action, including when no agents exist. Use `/durable new` to open creation directly; `/durable create` is an equivalent spelling. `/durable list` remains a noninteractive inventory.

The creation form collects the name/ID, existing absolute base folder, instructions, task profile, model policy, and optional PR repository. Prefill the folder editor with Pi's current working directory and let the user replace it, preserving spaces and platform-native separators. Review the exact folder, derived project directory, model policy, event behavior, and independent process before installation or startup. The terminal review keeps its title and actions visible while PgUp/PgDn or Up/Down scroll literal configuration text. Use Tab or Left/Right to choose Cancel/Create, then Enter; Cancel is selected initially and Escape also cancels. RPC retains its structured confirmation dialog. Cancelling before this review completes writes nothing.

Create the standalone application at `<base-folder>/.pi/durable/<agent-id>/`, refusing an existing destination. The service's `workspaceRoot` is the chosen base folder, while its source, prompts, state and logs remain in its own project. Workspace tools provide bounded directory listings and UTF-8 text reads; they reject traversal, symlink escapes, credential/state directories and binary/oversized files. The generated agent has read-only local tools. Folder selection does not grant shell execution or file modification.

The console installs locked project dependencies, builds the application, starts its own background Node process, verifies the authenticated agent registry, and adds the service to the current connections file. It reuses the installed Pi's read-only Codex credential bridge without copying credentials. Creation and idle registration make no model generation requests. Manual chat is the default event mode; an explicit repository selection enables PR polling with a baseline scan. Use `latest` plus a task profile for current task-aware selection, a family policy for a fixed family, or an exact model ID. See [model selection](model-selection.md).

Show preparation progress and retain diagnostic files if installation or startup fails. Report a running agent only after readiness and registry registration succeed. A created process continues after Pi closes; login startup is a separate deployment action. Existing services and jobs need no restart. After creation, offer to open its chat immediately.

For a programmatic review without creation, import `prepareAgentCreation` from the generated `src/agent-creation.ts`. Its input is `{id,name,baseDir,instructions,task?,model?,thinkingLevel?,repository?}`. Its context is `{cwd,extensionDir,connectionsFile?,provider?}`; use `provider:'faux'` for offline preparation. Create the existing base directory as a task artifact first. Run the helper with the generated package's `tsx`, for example `node --import tsx prepare-plan.mjs` from the console directory. Serialize the returned frozen public plan to the requested JSON path. Preparation reads the local template and checks installed JavaScript entry paths; it creates no project, starts no service, reads no account credentials, and resolves no live model. The plan exposes `baseDir`, `projectDir`, `configPath`, `connectionsFile`, `target`, `requestedModel`, `task` and `provider`. `createAgent(plan,{signal?,onProgress?})` is a separate mutation and requires that same in-memory reviewed plan; a saved JSON plan cannot authorize creation.
