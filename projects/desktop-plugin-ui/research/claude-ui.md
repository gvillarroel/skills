# Claude Desktop plugin UI research

Checked on 2026-10-24. This is a source review of official Anthropic and Model Context Protocol material. No Claude Desktop installation, connector, account, or live rendered app was tested. Treat every positive below as **documented**, every optional capability as **conditional**, and every prohibition as a **documented boundary**, not an observed execution failure. The user's phrase “Cloud Desktop” still requires product identification; these findings apply only if it means **Claude Desktop**.

## Product and transport boundaries

- Claude's current interactive-connector help documents inline cards and fullscreen interfaces on Claude Desktop. An enabled connector with an interactive interface can appear automatically for relevant tasks. Administrators can disable the UI-rendering tools while preserving text tools. Purchases through third-party interactive connectors are unsupported. [Interactive connectors](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude).
- A Claude plugin packages skills, connectors, and subagents. Skills and commands work in Desktop Chat; hooks and subagents run in Cowork or Claude Code. Local MCP servers supplied by a plugin run in Cowork and Claude Code, not chat. Do not infer an interactive UI from the word “plugin.” [Plugins](https://support.claude.com/en/articles/13837440-use-plugins-in-claude).
- Desktop Extensions (`.mcpb`) package local MCP servers and offer host-generated installation/configuration screens. Packaging does not itself establish an MCP App rendering contract. [Desktop Extensions](https://www.anthropic.com/research/desktop-extensions).
- Remote custom connectors originate from Anthropic's infrastructure, even when used in Desktop. A server accessible only through the user's localhost, VPN, or private network is not reachable through that route. Desktop-configured local MCP is a separate mechanism and is unavailable in Cowork or claude.ai. [Remote connector networking](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).
- MCP Apps is an extension, not a guarantee attached to core MCP support. A server links a tool to an HTML resource and a supporting host renders the View in a sandboxed iframe. Keep a usable text result when the host lacks UI support. [MCP Apps overview](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html).

## Boundaries to keep explicit

- Sandboxed Views cannot manipulate the host DOM or inherit host cookies/storage. Browser UI code and the local MCP server have different authority. [MCP Apps overview](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html).
- Sampling, PiP, file export, permissions, resource access, and context updates require a host-capability and execution check. Availability in SDK typings is insufficient evidence of Claude Desktop behavior. [App API](https://apps.extensions.modelcontextprotocol.io/api/classes/app.App.html).
- A working static browser page proves rendering in that browser. A reference MCP Apps test host proves that reference integration. Neither proves a connector appears in the user's Claude build. [Official quickstart test-host workflow](https://apps.extensions.modelcontextprotocol.io/api/documents/quickstart.html).
- Native OS windows, arbitrary sidebar insertion, custom host toolbar buttons, and modifying Claude's shell are **unverified here**. Do not call them supported or impossible without a specific official contract and a safe target-host test.

## Host test record to collect

Record OS, Claude build, Chat/Cowork/Code surface, account plan, extension or connector version, local/remote route, SDK version, negotiated capabilities, exact action, expected result, observed result, console/protocol errors, screenshot, and timestamp. Use a disposable read-only data source. Exercise one successful path and one failure path per selected pattern. Report `documented`, `observed-working`, `observed-failed`, `conditional`, `unsupported`, and `untested` separately. A missing UI alone needs diagnosis before becoming a general unsupported claim: verify enabled tools, tool-resource metadata, MIME, resource reads, iframe handshake, CSP, and account/admin controls.

## Source drift

Official documentation is evolving quickly. The MCP Apps quickstart and repository currently describe split MCP SDK v2 packages; avoid copying a version-pinned older scaffold as current guidance. The wire protocol is documented as compatible between ext-apps 1.x and 2.x. [Official ext-apps repository](https://github.com/modelcontextprotocol/ext-apps). Recheck sources when recommending installation, distribution, or host-specific APIs.
