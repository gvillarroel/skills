# Frozen exploratory method: code-assist costs

The decision is not simply which model has the cheapest token. Minimize either
expected spend per accepted correct task, or spend plus the loss from an
undetected error and an exhausted task. Report both, subject to an assumed 95%
correct-completion floor and at most 1% undetected errors. These are illustrative
requirements, not requirements supplied by the user.

## Boundary and evidence

Execute only the local mathematical model and its validation and analysis
programs. Never invoke Pi, Copilot, a model API, a real target tool, or a live
evaluation. Harnesses are represented by configurable instructions, tool
definitions, batching, cache and compaction policies. A product name does not
create an intrinsic token discount. Identical ledgers and billing routes cost
the same. Availability of each control in a particular harness is unresolved.

Prices are the official sources frozen in `study-20260906.json` on September 6,
2026. Use Copilot token billing for the primary comparisons. The direct-API Luna
tier boundary is a separate route sensitivity, not a silently substituted rate.
Four selected models are not an exhaustive market search. The controls do not
include Google's seat-based Code Assist pricing, local self-hosting, legacy
request-priced subscriptions, or all available models.

All workload and correctness inputs are explicitly synthetic. The
[Chroma context-rot study](https://www.trychroma.com/research/context-rot) and
[Lost in the Middle](https://arxiv.org/abs/2307.03172) motivate variation in
length, location and information-loss mechanisms. They do not calibrate a
universal onset or the current models' coding accuracy. The 100k default rot
onset and 50k–400k sensitivity are modeling choices, not measured failure
thresholds. No empirical success claim follows from a passing simulator audit.

## Request ledger

Each attempt begins cold with system + tool-schema + task-background tokens.
Each tool wave produces model argument tokens and synthetic tool-result tokens;
retained tokens enter subsequent requests. Independent calls may share a wave,
but dependent tools cannot. There is one final answer request.

For each request, input I = ordinary U + cached-read R + cached-write W, with
disjoint buckets. Cost in USD is `(U*pU + R*pR + W*pW + O*pO)/1e6`, applying the
full-request long-context multipliers only when I strictly exceeds the selected
route's tier boundary. W is not an extra surcharge on U. Output includes the
assumed billable generated tokens, not just user-visible answer length.

Cache validity depends on prefix identity and elapsed time. TTL realization is
assumed: 1800 seconds for selected GPT models and 300 seconds for Sonnet, with
600-second pauses every fifth wave. The latter is not measured Copilot behavior.
One-hour caches, cross-session reuse, early cancellation, arbitrary provider
eviction, and routing-affinity failures are omitted and documented.

If accumulated input exceeds a cap, the compactor first reads that complete
input, including overshoot, and writes a summary. Only then is main-call context
rebuilt from static prefix + 10k summary + 20k recent tokens. The baseline
compactor reads uncached and loses cache. A declared alternative can read cache
and preserve the static prefix. A cap of 200k therefore does not guarantee that
the compaction request avoids the >200k price tier. No context truncation or
summary call is free.

## Quality, validation and retry equations

The smooth model subtracts `rot_beta * exposure` from baseline correctness log
odds, with exposure measured in 100k tokens above onset and late-call weighting.
Weighted retained evidence from summaries adds `log(fidelity)` to log odds.
Trimming, removing tools and shortening model output have explicit penalties.
The rival critical-cliff model uses peak exposure, a threshold penalty and
requires all assumed critical facts to survive every summary. The no-rot world
has no such penalties. These mechanisms are stress scenarios, not inferred laws.

The first attempt is validated. Correct output is accepted with specificity;
incorrect output escapes with one minus sensitivity. Rejected attempts can get
one fresh-context retry with the same or an escalated model. Outcomes across
attempts mix independent correctness and a shared uniform task-difficulty
variable. The mixture weight is not generally the Pearson correlation.

Exact terminal probabilities distinguish accepted correct, accepted incorrect,
and exhausted tasks. Expected spend counts all reached attempts. Cost per
correct completion is the ratio `E[spend] / P(accepted correct)`, a long-run
aggregate ratio, not an expected random per-task ratio and not an unlimited
retry model. Loss-adjusted cost adds user-replaceable USD/error and
USD/exhausted-task assumptions. Correct-but-rejected exhausted tasks still
require recovery under this objective.

## Design and inference

The core includes 17 profiles x 4 models x 3 workloads x 3 quality worlds: 612
exact expectation cells, with 24 prespecified non-worsening contrasts. The
zero contrast threshold screens direction; report magnitude separately. Each
contrast has long/smooth as primary and all other points as challenges. Exact
arithmetic of the probability model has no Monte Carlo sampling error, but it
retains substantial parameter and structural uncertainty.

The namespaced extension exhausts a predeclared finite grid of 5760 policy
configurations per workload/world: 51840 cells. Rank by raw token spend,
loss-adjusted spend, and spend/correct under the quality constraints; report
infeasibility rather than relaxing a failed constraint. Report minimax regret
across the three worlds without treating their unweighted frequencies as
probabilities. Grid search is exploratory selection, not out-of-sample evidence.

Supplemental one-factor sweeps were specified before outcomes: summary fidelity,
retry dependence, rot onset, idle duration, rework loss, and the Luna route tier.
A ten-request hand-calculable prefix case isolates 1000 extra system tokens.
Primary traces have 6, 11 and 39 main calls before any compactions or retries.
Removing a required tool is not presumed equivalent to harmless batching.

The monthly extension uses the exact disjoint terminal distribution as a
multinomial generator, not a million-loop target run. There are 20000 synthetic
months per selected policy/volume, using 60% short, 30% feature, 10% long tasks.
Each month shares a declared difficulty shock: probabilities 0.83/0.15/0.02 and
log-odds shifts 0/-0.5/-1.5. Conditional tasks are independent. These invented
process probabilities are distinct from uncertainty about the three rival
quality models, which has no probability distribution assigned.

Report monthly mean, Monte Carlo standard error, predictive p05/p95, and budget
exceedance at 1.05 times the normal-month exact expected spend. The percentile
range describes variability under that synthetic process, not confidence that
reality is inside it. A 95% Hoeffding interval for a risk probability uses the
20000 independent months; do not claim simultaneous coverage for all reports.
Never scale a task percentile by task count.

For each monthly subscription, bill `fee + max(token usage - allowance, 0)`.
Non-token fees are additional. Mean-usage invoice projections and the expected
invoice integrated over simulated monthly usage are separate quantities. The
current variable flex credits can change; no Auto discount is granted to fixed
model routing. One million tasks is a mathematical scale projection, not a
verified quota, throughput, or account-eligibility claim.

## Verification and retained limitations

Before full results, check hand arithmetic, price discontinuities, cache
partitioning, TTL expiry, prefix churn, batching dependencies, compaction
overshoot, probability mass and independent two-attempt closed forms. Produce
an activation witness for every declared model parameter. These witnesses show
local influence, not global sensitivity magnitude or completeness.

The core skill validator recomputes declared contrasts and file integrity.
The extension separately records code/input hashes, table schemas, row counts,
independent probability/spend checks and Monte Carlo settings. It is not
certified by the core validator. Revisit the preflight variable inventory after
results, preserve decision reversals and unresolved omissions, and do not
retrofit the frozen specification to make a selected policy look better.
