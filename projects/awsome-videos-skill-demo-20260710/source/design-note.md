# Design Note

Concept claim: A skill is a reusable, validated workflow package that replaces repeated prompt baggage and wakes only when relevant.

Chosen visual metaphor: A semantic workbench built from recognizable technical objects. Repeated instruction sheets bind into a red SKILL packet; that same packet opens a resource shelf, organizes three production stations, routes a visual request, accompanies an artifact through validation, occupies the compact side of a context comparison, and reactivates across several project surfaces.

Persistent element: `red SKILL packet`. It is a red document with a folded white corner and the visible label `SKILL`. Its silhouette, label, and color remain stable. Its role changes from bound instructions to package, active core, organizer, routing contract, validation companion, compact context core, and reusable library item.

Rejected metaphors:

- An abstract systems canvas was rejected because unlabeled rectangles and routes required narration to acquire meaning.
- A detached proof window was rejected because it made the source-bound asset subordinate to decorative geometry.
- A generic toolbox was rejected because it hides activation timing and progressive disclosure.
- A plug-in cartridge was rejected because it makes resources, specialist routing, and validation too linear.
- Text-only slides and generic stock footage were rejected because they do not demonstrate causal workflow behavior.

Visual vocabulary: White and grayscale work surfaces carry hierarchy; red marks active workflow state, selection, rejection, and correction. Recognizable objects include project windows, instruction sheets, folders, documents, a terminal, a media frame, a producer switch, a chart, a flowchart, an illustration, an inspection conveyor, context trays, and project surfaces. Functional Spanish labels attach directly to those objects. No moving shape exists only to keep the frame active.

Composition contract: 1280x720, fixed-frame scene ownership, hard-edge geometry, external gutters, and safe margins. Each manifest-bound SVG occupies 70–85 percent of frame width and height. Eight scenes use at least five materially distinct layouts: causal strip, centered hero, asymmetric selection corridor, three-station workbench, branching switchboard, inspection conveyor, split comparison, and reuse hub. There is no detached proof window; the file-backed asset is the primary scene.

Motion contract: Every scene exposes input, process, output, and active state. Motion verbs are semantic: copy, bind, open, select, load, execute, route, reject, correct, approve, compare, and reactivate. Each seam changes the role of the red SKILL packet or the artifact it accompanies. A generic pulse, pan, or route line is insufficient on its own.

Asset-routing decision: Use deterministic SVG for exact labels and technical object geometry. The specialist-routing scene visibly distinguishes a conventional diagram, bespoke data geometry, and a generated-illustration surface so Mermaid, D3, and ImageGen roles do not collapse into one anonymous visual language.

Narration split: Spanish narration carries definitions, caveats, and the qualitative context claim. Frames must independently carry recognizable input, visible action, and visible result. The muted hold frame and eight-frame contact sheet are explicit acceptance surfaces.
