# Lucidchart SVG fidelity: vendor evidence audit

Checked: 2026-10-07. Scope: SVG custom-shape import, Standard Import image embedding, and SVG export. This is a documentation audit using Lucid help/developer documentation and identified Lucid staff replies. No Lucid import/export round trip, authenticated UI action, or account change was performed in this audit.

Lucid supports importing SVG as a custom shape, but this does not establish lossless SVG round-tripping or independent native editing of every source element. The selected import route and rasterization mode materially affect what survives. Visual similarity, vector representation, editable labels, and native connector behavior must be assessed separately.

## Evidence matrix

| Route or detail | Documented behavior | Remaining uncertainty or loss | Verification needed |
| --- | --- | --- | --- |
| SVG through the custom-shape library | Lucid documents SVG upload through **More shapes → Import Shapes → existing/new library → Choose File → Upload**. It identifies SVG/stencil import as a premium feature. [Shape libraries, updated 2026-09-09](https://help.lucid.co/hc/en-us/articles/14931750819476-Shape-libraries-in-Lucidchart) | File-type acceptance is not a guarantee that every SVG feature renders identically. | Record import control, account entitlement, and any rasterization warning/option; compare actual imported appearance. |
| Formal SVG import with rasterization disabled | Lucid staff distinguish formal SVG import, which can retain vector properties, from SVG canvas drag/drop, which treats the file as a regular image. A 2026 staff reply also discusses importing simple icons unrasterized. [Official scaling discussion](https://community.lucid.co/product-questions-3/how-can-i-scale-svgs-while-retaining-quality-7004/index2.html) | Vector retention does not prove unchanged path geometry or complete SVG feature coverage. The staff guidance is conditional on the result looking correct. | Compare curved edges, joins, overlaps, and thin strokes at normal size and high zoom. Re-export and inspect vector/image elements. |
| Custom-shape import with **Rasterize SVG Imports** | Lucid staff acknowledge this option and, on 2026-06-05, describe changing source dimensions as the existing workaround for import raster resolution control. [Official scaling discussion](https://community.lucid.co/product-questions-3/how-can-i-scale-svgs-while-retaining-quality-7004/index2.html) | This is a raster route. No general documented output-resolution formula was found; the example workaround is not a universal guarantee. | Record source dimensions and resulting pixels; compare at the intended output size. Do not select this mode when vector preservation is required. |
| SVG internal components as editable objects | In a 2024 support answer, an imported icon plus textbox was treated as one object, preventing separate resizing of those components. [Imported SVG shape behavior, staff answer 2024-11-06](https://community.lucid.co/product-questions-3/imported-svg-shape-not-behaving-as-expected-9056) | Do not infer separate native nodes, text areas, or attached connectors from visual resemblance. This case documents a limit, not every possible SVG shape configuration. | Try selecting internal components, editing a label, and moving a node while checking attached connectors; undo probes. |
| Live text inside an imported SVG | A historical 2021 staff reply suggests non-path SVG text might be editable, but qualifies its behavior and recommends overlaying a separate Lucid text shape. [Import SVG with editable text](https://community.lucid.co/product-questions-3/import-svg-with-editable-text-3568) | This is qualified historical guidance, not a current guarantee. Text rendered into paths has no source text characters to recover directly. | Test text selection/editing and literal label recovery in the current import mode. Preserve original label strings separately. |
| SVG as an image in a Standard Import package | The developer reference explicitly states that an uploaded `.svg` image is converted to `.png` before it is included in the created document. [Standard Import Images](https://developer.lucid.co/docs/images-si) | Vector structure, text semantics, and graph semantics are not preserved through this image route. The reference does not specify the conversion resolution or guarantee visual parity for all SVG features. | Inspect generated image resolution and rendering. Use explicit native graph reconstruction when separately editable objects are required. |
| Lucidchart export to SVG: text and fonts | Lucid support confirmed on 2025-07-05 that SVG export renders text as vector paths and does not export live text. [SVG export and editable text](https://community.lucid.co/ideas/exporting-a-lucid-document-as-a-svg-with-editable-text-2974) | Outlined glyphs can preserve an appearance while losing editable/extractable labels and font metadata. Appearance retention is an audit inference, not a pixel-level vendor guarantee. No new live output was checked. | Inspect actual exported XML for `text`/`tspan` versus glyph paths/`use`; compare label appearance and retain a separate label/graph manifest. |
| SVG export: crop and collaboration detail | The help article documents crop-to-content/custom crop for SVG and says tags, emoji reactions, notes, and comments do not appear in the exported document. [Export help, updated 2026-09-10](https://help.lucid.co/hc/en-us/articles/16324571257492-Export-or-print-a-Lucid-document) | An export is a visual artifact with documented omissions, not a complete document-state backup. Crop can also deliberately omit content. | Compare full page boundaries, labels near the crop edge, and requested page coverage; record omitted collaboration metadata. |
| Filters, masks, clipping, CSS, custom fonts, embedded/external images, animation | A historical support answer acknowledged no standard SVG import requirements guide and suggested path simplification for a problematic SVG. [SVG import requirements, staff guidance 2021](https://community.lucid.co/product-questions-3/what-are-the-requirements-for-svg-imports-in-lucidchart-1250) | The current sources inspected do not establish comprehensive compatibility or preservation guarantees for these features. Do not turn this absence of evidence into a claim that a feature always fails. | Use feature-specific fixtures; compare source, imported canvas, and exported SVG. Inspect dependencies and raster content. Any simplification needs a separate derivative and loss note. |

## Decision and evidence boundary

For vector artwork, prefer the formal custom-shape route with rasterization disabled when the current UI offers it, and verify visual fidelity. For editable diagram meaning, explicitly reconstruct nodes, labels, and edges, then test their native behavior. Standard Import embedding cannot serve as vector preservation because SVG-to-PNG conversion is documented. SVG export should not be assumed to preserve searchable/editable labels because Lucid staff document outlined text.

No numeric fidelity score or pixel-difference claim is justified by these sources. A release-quality live check should retain the original SVG, exact import settings, canvas screenshot, returned SVG bytes, and a per-feature loss ledger. Compare visual detail at the intended scale and high zoom; separately check text editability, object separation, and connector attachment. Historical staff answers should be treated as dated evidence and rechecked against current service output.

Source selection excludes unsupported claims from ordinary forum users. The matrix uses explicit staff statements where community pages are cited; no browser-specific workaround or report of missing vector vertices has been promoted into a universal product guarantee.
